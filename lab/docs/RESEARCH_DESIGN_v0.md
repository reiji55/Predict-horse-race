# AI競馬確率研究 — 現状分析と研究設計 v0（ドラフト）

- 作成: 2026-10-16 / Claude（実装・データ処理担当）
- 監査予定: ChatGPT（研究方針・仮説・独立検証・コード監査）
- 状態: **ドラフト。ChatGPT のレビューとオーナーの判断（§7）を経て v1 として確定する**
- 対象リポジトリの基準コミット: `1eb43f7`（main）

## 0. 研究の問い

> **RQ1**: 発走前に入手できる情報だけで、JRA平地競走の勝率分布を、**同じ時点の市場オッズから得た確率より**正確に推定できるか（out-of-sample の log loss で測る）。
>
> **RQ2**: RQ1 で市場を上回れた場合、その差は控除率（単勝20%・馬連/ワイド22.5%・3連複25%）を超える期待値を生み、**未知のレース**で長期的に回収率100%を超えるか。

RQ2 は RQ1 が成立したときだけ検証する。RQ1 が不成立なら、どんな買い方を工夫しても長期的な収益は期待できない（市場より悪い確率で期待値を計算しているため）。

## 1. 既存リポジトリの分析結果

### 1.1 現行モデル（Champion `win-v1-speed-guard`）の構造

| 項目 | 内容 |
|---|---|
| 確率の作り方 | 3因子（speed 0.45 / aptitude 0.30 / human 0.25）をレース内でz標準化して加重和 → `70+10z` に変換 → softmax(T=10)。`logic/base_score.py`・`logic/prob_model.py` |
| 重み・温度 | **手で決めた値。データから学習していない**。T は仕様書上も「仮値・後で較正」（妙味メーター仕様§7 #2、OPEN_QUESTIONS B-6） |
| オッズの扱い | 確率モデルにはオッズを入れない（妙味＝p−q の循環を避けるため）。市場確率 q は 1/odds の単純正規化 |
| 対象 | 土日の各場11R のみ（`config/scraper.json`） |

### 1.2 強み（研究にそのまま活かせる資産）

1. **発走前スナップショットの凍結と採点の分離**（`data/snapshots/`）。発走後のビルドで予想が上書きされない仕組みが、すでに実戦で1度事故（OPEN_QUESTIONS E-1）を経て固められている。
2. **事前登録の文化と仕組み**。`race-performance-v1` の事前登録（設定ファイルの SHA-256 固定）、`registered_at` 以降だけを forward 評価、paired log loss / Brier を主指標にする、など研究に必要な規律はすでにある。
3. **再現性のメタデータ**。snapshot ごとに `git_commit`・`config_hash`・`base_times_hash` を記録している。
4. **市場ベースラインとの比較がすでに評価式に入っている**（`q_market_reference`）。
5. **オッズの時系列**（`data/odds_history/`、1レース1〜5時点）と馬場情報（`track_metrics`）の取得経路がある。
6. Champion/Challenger・shadow・chat-experiment がすべて「本番に混ぜない」設計になっている。

### 1.3 弱み

1. **学習していないモデル**。重み・温度・閾値が手設定なので、データが増えても精度は上がらない。較正（予測確率と実際の勝率の一致）も未調整。
2. **確率が平らすぎる**。モデルの最大 p は 0.16〜0.29 に収まり、市場の1番人気（最大 0.35）より常に控えめ。
3. **特徴量が浅い**。過去5走のみ。通過順位・ペース・上がり順位・過去走のオッズ/人気・血統・調教・斤量の変化・枠の有利不利などがない。
4. **騎手・調教師成績が「今年の累計（取得時点）」**。過去のレースに当てはめると未来の成績が混ざる（後述 §3.2）。
5. **ROI が少数の高配当に支配されている**（§1.5）。

### 1.4 予測精度 — 市場との比較（今回の再計算）

`data/snapshots/` の発走前予想（18レース、20260921阪神11Rはオッズ欠損で除外）と確定着順で、**勝ち馬の log loss**（小さいほど良い）を計算した。市場確率は**凍結時点の**単勝オッズを正規化したもの。

| 予測 | 平均 log loss | 備考 |
|---|---|---|
| 一様分布（全馬同じ確率） | 2.729 | 何も知らない基準 |
| **Champion** | **2.627** | 一様より −0.102（SE 0.184） |
| **市場（凍結時点のオッズ）** | **2.512** | Champion より −0.115（SE 0.144） |

既存の forward 評価（`data/shadow/model_evaluation/*/summary.json`）も同じ方向を示している:

| 評価 | n | Champion | Challenger | 市場 |
|---|---|---|---|---|
| speed-v2 forward | 9 | 2.745 | 2.790 | 2.374 |
| race-performance-v1 forward | 6 | 2.411 | 2.280 | 2.148 |

**結論: 現時点で、どのモデルも市場より正確だという証拠はない。** 平均では市場のほうが良く、サンプルが小さすぎて差の有無も判断できない。凍結時点が朝8:36〜発走直前とばらついており、早い時刻のオッズは確定オッズより情報が少ないので、確定オッズと比べれば市場はさらに強くなるはずである。

### 1.5 収益（参考。判断には使えない）

| キャラ | レース | 購入 | 払戻 | 回収率 | 的中 |
|---|---|---|---|---|---|
| kei | 18 | 9,000 | 8,370 | 93% | 3 |
| tetsu | 18 | 9,000 | 53,920 | 599% | 4 |
| gen | 18 | 9,000 | 130,120 | 1446% | **1** |
| chappy | 14 | 14,000 | 15,800 | 113% | 4 |

gen の回収率はたった1回の的中で決まっており、それを除くと0%。18レースの回収率はほぼノイズで、モデルの良し悪しの根拠にならない。

### 1.6 データの充足状況

| データ | 量 | 研究での使い道 |
|---|---|---|
| `raw/2026-W38〜W42.json` | 5週・約20レース（11Rのみ）、各馬の過去5走・単勝/複勝/馬連/ワイド/3連複オッズ | 形式の参考のみ。**オッズは発走後に取り直した確定値で上書きされている**（例: W41 は 19:43 取得、`odds_updated_at` は発走後）ので、発走前の特徴量には使えない |
| `data/snapshots/` | 19レース | 現行モデルの発走前予想。Champion の再評価用 |
| `data/odds_history/` | 14レース × 1〜5時点 | 「判断時点のオッズ」と「確定オッズ」の差の小規模な観察に使える |
| `data/race_results.json` | 19レースの着順・払戻 | 採点用 |
| `data/reference/base_times/sources/…records.json` | 2023-01〜2026-09 の **12,469レース**（ただし勝ちタイム・クラス・馬場などレース単位のみ） | 基準タイムの再構築には使える。**馬ごとのデータがないので確率モデルの学習には使えない** |
| 騎手リーディング | 取得時点の年間累計。最新週で充足率 42% | 過去時点の値を再現できないので使わない（自前で再計算する） |

**結論: 学習・検証に使える規模の過去データは、リポジトリにまだ存在しない。** 確率モデルを学習・検証するには、最低でも数年分・全レース・全出走馬の「出走時点の情報＋結果＋オッズ」が必要（§4 Phase 1）。

### 1.7 必要なサンプル数の目安

- **確率の精度（RQ1）**: 市場との差がレースあたり log loss 0.01、レースごとの差の標準偏差が 0.15〜0.6 なら、片側5%で検出するのに **約600〜10,000レース** 必要。11Rだけ（週4〜6レース）では数年かかるので、**研究の対象は全レース（年間約3,400レース）に広げる**必要がある。
- **収益（RQ2）**: 平均オッズ10倍前後の単勝で回収率+5%を検出するには、**約1万点の賭け**が必要。収益の確認には、確率の確認よりはるかに多いサンプルが要る。

### 2.3 CI での隔離

- `lab/` 専用の workflow（`lab_ci.yml`）で lab のテストだけを回す。既存の `ci.yml` は変えない。
- lab の PR が `lab/` 以外のパスを変更していたら CI を失敗させるガードを入れる。
- lab の workflow は本番データ（`data/` `raw/`）にコミットしない。

### 2.4 データの置き場所（要判断 §7）

リポジトリは**公開**である。数年分の出走データは容量が大きく、取得元の規約上、再配布できない可能性が高い。**生データと学習用データベースは Git に入れず**、Git には「コード・設定・事前登録・集計結果・データの SHA-256」だけを残す。

## 3. 過学習・未来情報の混入を防ぐ設計

### 3.1 データの分割（時系列で固定）

```
|---- 開発（Dev） ----|-- 検証（Val）--|-- 封印ホールドアウト --|-- 前向き検証（Live） -->
   例: 〜2023年末        2024年          2025-01〜2026-09        2026-10以降の未発走レース
```

| 区間 | 使い方 |
|---|---|
| Dev | 特徴量・モデルの開発。walk-forward（拡張窓、月単位で学習→翌月を予測）で何度でも評価してよい |
| Val | ハイパーパラメータとモデル候補の選択。見てよいが、見た回数を記録する |
| **封印ホールドアウト** | **事前登録した最終候補を1回だけ評価する**。評価のたびに `lab/docs/reports/holdout_access_log.md` に記録し、2回目以降は「探索的」と明記する。区間の境界は v1 確定時にコミットで固定 |
| Live | 研究開始後に発走するレース。発走前に予測をコミットし、結果後に採点。**最も強い証拠** |

※ 年の区切りは、確保できる過去データの期間が決まってから v1 で確定する。

### 3.2 未来情報（リーク）の防止

すべてのデータに「いつ入手できたか（`available_at`）」を持たせ、特徴量は **判断時刻 `as_of` より前に入手できたものだけ** から計算する。

| 既知の危険 | 対策 |
|---|---|
| 確定オッズで予測する（`raw/` は発走後に上書きされている） | 予測には判断時刻のオッズだけを使う。過去データで判断時刻のオッズがない場合は「確定オッズを使った楽観的な上限」と明記して分けて報告 |
| 騎手・調教師の「今年の累計」 | 過去レースの結果から `as_of` 時点の成績を自前で再計算する |
| 基準タイム表（v2 は 2026-09-27 までの勝ちタイムから作成） | 基準タイムも walk-forward で `as_of` までのデータから作り直す |
| 長期の戦績を発走後に取ると、当該レースの結果が含まれる | 過去走は `run.date < race.date` で切る（既存の history_inventory と同じ規則） |
| 当日の馬体重・取消・馬場状態 | 判断時刻に公表済みかを `available_at` で判定 |
| 特徴量の正規化（平均・標準偏差）を全期間で計算 | 学習区間だけで計算する。レース内の正規化は問題ない |
| 結果を見てから作った仮説 | 事前登録してから Val / ホールドアウトで評価する |

**自動テスト**:
1. 時点切り捨てテスト: データベースを `as_of` で切り詰めて計算した特徴量が、全データで計算した特徴量と完全一致すること。
2. 未来シャッフルテスト: `as_of` より後のデータをランダムに書き換えても、特徴量が変わらないこと。
3. 特徴量ごとに `available_at` の宣言を必須にし、宣言のない特徴量はモデルに入れない。

### 3.3 過学習の防止

- 主指標は1つ（race 単位の勝ち馬 log loss の市場との差）に固定し、事前登録する。
- 試したモデル・特徴量の数を記録し、多重比較を考慮する（試した数が多いほど、ホールドアウトで求める差を厳しくする）。
- 不確実性は**レース単位の bootstrap**で出す（馬単位で数えると独立でないため過小評価になる）。
- ROI は主指標にしない。最大払戻レースを除いた ROI も必ず併記する。

## 4. ロードマップ

| Phase | 内容 | 完了の条件 |
|---|---|---|
| **0. 基盤** | `lab/` の骨組み、隔離ガード付き CI、本設計書の v1 確定（ChatGPT 監査済み） | lab の PR が本番パスに触れると CI が落ちる |

| **2. 市場ベースライン** | 確定オッズの確率化（単純正規化・べき乗法・Shin法など）を比較し、市場の較正（人気薄の過大評価＝favourite-longshot bias）を測る。`odds_history` で判断時刻と確定の差も観察 | 「市場の log loss」という超えるべき基準線が数値で確定 |
| **3. 基礎モデル** | オッズを使わない確率モデル（条件付きロジット、勾配ブースティング＋レース内 softmax など）。walk-forward で評価 | 一様分布・Champion 再現より良いことを Val で確認 |
| **4. 統合モデル** | 基礎モデルの確率と市場確率を組み合わせる（市場確率を入力の1つとして学習）。**市場単独より log loss が下がるか** が RQ1 の答え | 事前登録 → ホールドアウト1回評価 |
| **5. 期待値と賭け方** | 単勝から組合せ馬券の確率を推定（Harville とその補正）、控除率・自分の購入によるオッズ変化を考慮した期待値、分数ケリー等の資金配分をシミュレーション | 事前登録した賭けルールでホールドアウトを1回評価 |
| **6. 前向き検証** | Live 区間で発走前予測をコミット（紙上の賭け）。既存の chat-experiment と同様、Git のコミット時刻で発走前性を証明 | 事前登録したサンプル数に達するまで結論を出さない |
| **7. 本番への還元（任意）** | 結果が出た場合のみ、既存の Champion/Challenger 手順（`docs/MODEL_OPERATIONS.md`）で Challenger として提案 | 本番オーナーの判断 |

Phase 2 だけでも、「市場はどれくらい正確か」「人気薄はどれくらい過大評価されているか」という研究価値のある結果が出る。

## 6. 期待値の現実的な見通し

- 競馬の市場オッズは公開情報をよく反映しており、単独で市場を上回るモデルを作るのは難しい。先行研究（Benter 1994 など）でも、成功例は「基礎モデル＋市場確率の統合」で、市場単独からの改善はわずか（ただし控除率を上回るには十分だった）。
- 控除率が単勝で20%、3連複で25%あるので、**確率の精度が市場とほぼ同じでは確実に負ける**。人気薄の過大評価など市場の歪みを、どれだけ確実に拾えるかが鍵になる。
- 研究の結論が「市場を上回れない」となる可能性も十分ある。その場合もそれを正しく結論づけることを、研究の成果とする。
