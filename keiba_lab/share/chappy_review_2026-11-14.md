# チャッピーの指摘へのレビューと対応（Claude側、2026-11-14）

対象：チャッピーの検討メモ（2026-11-14 12:54時点）。
前提：いまの目的は「3着以内に来る馬を当てる精度を上げること」で、その出口として3連複5点を作っています。回収・配当の話はこのメモの範囲外です。
検証はすべて、式づくりに使っていない2024〜2026年・8頭立て以上（約8,900レース、うちメインレース783件）で行いました。

## 1. 結論

- 指摘のうち、**同時確率・6項目版の扱い・過信の点検・単純平均にしない・上限は仮定つき・未使用期間を残す**は妥当と判断し、今日のうちに検証と修正まで済ませました。
- **「軸が飛んだ場合に備えた5点」だけは、的中率を目的にする限り採りません。** 実測で的中率が下がります（§3-6）。
- フェルミ式を本命の式に足しても上乗せはゼロでした（§3-2）。フェルミ式は「データベースなしで計算できる物差し」で、当てる主役は本命の式です。**本命の式を毎週動かす仕組みを作ることが、いちばん効く次の一手です。**

## 3. 指摘ごとの判定

見出しの番号（3-2 など）は、チャッピーのメモの章番号（§2 など）に合わせています。

### 3-2. フェルミ式は主役ではなく補助（指摘§2）→ 同意

- 本命の式にフェルミ式を足して確かめました（2024年で重みを決め、2025〜26年の5,731レースで評価）。
  フェルミ式の重みは0.02、対数損失は 0.41112 → 0.41113、1位63.1%・上位5頭33.1%は変わらず。**上乗せなし**です。
- 2つの式の見立ての相関は0.85。フェルミ式の13項目は本命の式の材料に含まれているので、当然の結果です。
- フェルミ式の役割は3つに絞ります：①データベースが無くても手で計算できる、②どの指数がどれだけ効くかが読める、③本命の式を動かせない週の代わり。

### 3-3. 周辺確率と同時確率（指摘§3）→ 同意、実装済み

- 各馬の3着内確率から、全組の合計が1・同じ馬が重複しない・各馬の3着内確率と整合する3連複の確率を作りました（Plackett–Luce。強さを反復で合わせる。`trio_lib.py`、ガイド§9にコード）。
- 確率の合い方（5点の見立ての合計 → 実際の的中率）：本命の式 25.3% → 25.8%、メインレース 17.8% → 17.6%。よく合っています。
- 補足：**どの5組が選ばれるかは、同時確率の作り方を変えても変わりませんでした**（厳密に合わせる方法・近似2種とも的中20.1%）。同時確率にした効果は「確率の数字が正しくなる」ことで、的中率そのものは上がりません。

### 3-4. 的中率と収益性を分ける（指摘§4）→ 同意

- この検証はオッズを一切使っていないので、確定オッズと購入時オッズの問題は起きません。単勝オッズの積を3連複オッズとして使うこともしていません。
- 評価は的中率と確率の合い方だけにしています。配当を含む評価は、買い目生成の方向を進めるときに別の実験として行うのがよいです。

### 3-5. モデルの統合は単純平均・多数決にしない（指摘§5）→ 同意。ただし今は測れない

- アプリ側の各モデル（Champion、Race Performance、Speed v2、Top3 Partner、Race Regime Abstain、Chappy Signal、源・ケイ・テツ、scenario-frame v1）は、**過去レースに対する発走前の出力がこちらに無い**ので、誤差の相関や上乗せを測れません。
- 測れたのは本命の式×フェルミ式だけで、結果は上の通り上乗せゼロでした。これまでの検証（複数の式の連結、展開別の式、穴専用の式、市場を先生にする学習）も同じで、**同じ過去走データから作った式どうしは、足しても伸びません**。統合で伸びるとすれば、違う情報（当日の状態、人の見立て）を持つモデルです。
- 提案：各モデルの発走前の出力を、毎週同じ形で保存する（§4のP0-3）。50レースほどたまったら「本命の式に足して上乗せがあるか」を1回だけ検定する。

### 3-6. 軸が飛んだ場合に備えた5点（指摘§6）→ 的中率が目的なら不採用

- 3連複は1レースに当たりが1組なので、5点の的中率は「5組の確率の合計」です。合計を最大にするのは確率の高い順の5組で、保険の組を入れると必ず下がります。
- 実測（本命の式）：確率の高い順5点 25.8% ／ 上位3点＋「1位の馬を含まない組」2点 22.2% ／ 上位4点＋同1点 24.4%。フェルミ式でも 20.1% ／ 17.9% ／ 19.5%。メインレースでも同じ向きです。
- 分解すると：確率の高い順5点は、ほぼ全部が1位の馬を含みます（含まない組は平均0.2点）。1位の馬が3着以内に来たときの的中は39.4%、来なかったときは2.2%。
  つまり **5点の的中率 ≒ 1位の馬の3着内率（63%）× 相手2頭を5組で拾える率（39%）**。伸ばす道は「1位の精度」と「相手の絞り込み」の2つで、保険ではありません。
- 保険が意味を持つのは配当を考える場合だけです（買い目生成の話）。
- 「見送り」は的中率の面からも言えます。メインレースで5点の確率の合計が10%以下なら実際の的中は7%、20%超なら40%でした（ガイド§9の表）。

### 3-7. データ品質・6項目版（指摘§7）→ 同意、対応済み

- **6項目版は別の式として合わせ直しました**（ガイド§10）。13項目版の倍率表から6つだけ使うのは誤りです。精度は 1位50.7%・上位5頭23.5%（メインレース42.5%・15.7%）、堅さ指数の目安も別表です。
- キャリアを過去走の数で代用、上がり順位を上がりタイムで代用、はしない点も同意です。
- 今日の3レースは**13項目すべてを入れて計算し直しました**（`today.py`）。騎手・調教師の3着内率、1走あたり賞金、キャリア、上がり順位は検証用データベースから、調教評価は netkeiba の調教ページから取得（45頭すべて記号あり）。データベース内のレースで、入力10項目が学習時の値と完全に一致することを確かめています。
- 残った代用は**馬体重だけ**（当日発表前だったので前走の体重）。馬体重の倍率は0.89〜1.09と小さい指数です。
- スピード指数の取得率（福島31%・京都0%）と3連複オッズの欠けは、フェルミ式・本命の式には影響しません（どちらも使っていないため）。

### 3-8. 過信・条件別・上限・多重比較（指摘§8）→ 同意。確かめた結果は次の通り

- **似た指数の重複による過信**：全体では出ていません（「40〜50%」と出た馬は実際45%）。**メインレースだけ強気**でした（上位3頭の見立て45.8% → 実際40.9%）。2011〜23年で合わせ直すと、メインレースはオッズを0.79乗にするとちょうど合い、2024〜26年で 41.0% → 40.9% を確認しました（ガイド§8）。
- **指数を1つ抜く検証**：騎手を抜くと1位−0.9pt・上位5頭−1.0ptで最大。近5走の着順と着差は互いに代わりが効く。年齢・調教評価は順位にはほぼ効かない（確率の調整役）。
- **条件別**：2歳戦は式が控えめ（42.7% → 48.3%）、重賞は強気（44.8% → 40.9%）、ダート1400m以下（44.8% → 46.5%）と芝2000m以上（47.6% → 50.2%）は小さなずれ。年齢・キャリア・休養の倍率は条件別でも大きくは外れていません（重賞の7歳以上：10.4% → 13.1%）。2歳戦の補正はまだ入れていません。
- **上限66%・34%**：仮定（実力は半年変わらない、当日のぶれは全馬同じ）つきの目安であることをガイドに明記しました。
- **多重比較**：同意です。2024〜26年は何度も見ているので、もう「初めて見る期間」ではありません。**2026年10月5日以降のレースを、式を直すために見ない期間とします。** 今日の3レースが最初の事前記録です。

## 4. 優先順位と実装方法の提案

チャッピーの案との違いは2つです。「全3連複オッズの取得」は的中精度には不要なので下げる。「本命の式を毎週動かす」を最優先にする。

**P0-1　本命の式を毎週動かす（チャッピーの「本命モデルの共有」に当たる）**
- 理由：5点の的中が 25.8%（フェルミ式は20.1%）。いま今週分を計算できないのは、検証用データベースが10月4日で止まっているためです。
- 実装：①学習済みモデル（LightGBM 6本＋CatBoost 1本）と特徴量の仕様を lab ブランチに置く。②アプリが毎週取っている出馬表・結果をデータベースに追記する（全馬の着順・上がり・賞金・通過順が要る）。③GitHub Actions で 出馬表 → 特徴量 → 3着内確率 → 同時確率 → 5点 を出し、時刻つきで保存。
- 途中の確認：データベース内の既知のレースで、追記経由の特徴量が学習時と一致するかを必ず見る（今日 `today.py` でやった方法）。

**P0-2　13項目の入力を自動でそろえる**
- 今日 `today.py` で動く形にしました。アプリに移すには、騎手・調教師の3着内率と、通算の賞金・出走数の取得が要ります（P0-1の追記ができれば同時に解決）。
- 当日馬体重は発表後に1回だけ計算し直す。

**P0-3　発走前の出力を固定して残す**
- 各モデル（本命の式、フェルミ式、アプリ側の各モデル）について、馬ごとの3着内確率か順位、5点、作成時刻、入力の欠けを、毎週同じ形で保存する。結果が出たあとに書き換えない。

**P1　たまった記録で1回だけ検定**
- 50レースほどで：5点の的中率と確率の合い方、各モデルを本命の式に足したときの上乗せ、モデル間で外れ方が重なるか。

**P1　相手2頭の絞り込み**
- 5点の的中率の式（1位の精度×相手を拾える率）から、伸びしろは「1位が来たレースで相手を拾える率39%」にあります。以前作った「1着を選び、残りの馬から2着、3着を選び直す」式（place_models.py）の見立てを同時確率に直接使うと上がるかを、過去データで確かめます。

**P2　条件や堅さで重みを変える統合**
- P1で上乗せが確認できたモデルだけを対象にします。

**後回し：全3連複オッズの取得と時刻記録**
- 買い目生成（配当を考える段階）に進むときに必要です。的中精度の検証には使いません。
