## 2. B（出馬表）で確定した重要な技術的発見

実サンプル2件（七夕賞2026＝枠順未確定段階、府中牝馬S2026＝枠順確定後）を比較して判明。

### 2.1 出馬表HTMLは「枠順確定前」と「確定後」で構造が変わる

| フィールド | 確定前 | 確定後 |
|---|---|---|
| td.Waku / td.Umaban | class・テキストとも空 | class="Waku1"等・テキストも数字 |
| 天候・馬場状態 | RaceData01に記載なし | "… / 天候:曇 / 馬場:稍" の形で記載 |
| 馬体重 | 空 | "470(-4)" の形式（パース済み） |
| 馬番の代替取得 | `<tr id="tr_{馬番}">` から取れる（odds/ninki spanのidとも一致確認済み） | 不要（テキストで取れる） |

→ b_shutuba.py はテキスト優先＋tr idフォールバックで両対応済み。枠番はフォールバック手段が無いため
確定前は None のまま返す（仕様上問題なし。当日朝運用なら基本「確定後」の状態のはず）。

### 2.2 グレード・レース基本情報の取り方

- グレードは見出し内の `Icon_GradeType{1,2,3}` から g1/g2/g3。それ以外はRaceData02の条件文字列
  （"オープン"→op, "３勝クラス"→3win 等）から判定
- 開催日はtitleタグから正規表現抽出、曜日はPythonのdatetimeで計算（土/日判定）
- レースIDはcanonical URLの `race_id=` パラメータ（12桁：年4+場2+回2+日2+R番号2）から取得可能

### 2.3 単勝オッズ・人気は静的HTMLに存在しない（★最重要の発見）

出馬表ページ・オッズページどちらも、オッズ・人気のセルは空の`<span>`で、**JS/AJAXが後から描画**する。
`requests`だけでの取得では原理的に埋まらない。

**解決策：オッズページが内部で叩いているAJAX APIを直接叩く（B2フェッチャーとして実装済み）。**

```
URL: https://race.netkeiba.com/api/api_get_jra_odds.html
パラメータ: pid=api_get_jra_odds, race_id={12桁ID}, type=all, action=init,
            output=json（jsonp剥がしを避けるため）, compress=1
必須ヘッダー: X-Requested-With: XMLHttpRequest, Referer: オッズページのURL
```

レスポンスは `{"status":"result","data":"<base64>", ...}` で、
`data`は **base64 → zlib解凍** すると本体JSONが出てくる（`compress=1`指定のため。
"eNp"始まりの文字列＝zlib圧縮データの目印）。

本体JSON構造：
```json
{
  "official_datetime": "2026-06-21 15:54:02",
  "odds": {
    "1": {"人気順key": ["単勝オッズ","0.0",人気,"馬番2桁"], ...},   // 単勝
    "2": {"...": ["複勝下限","複勝上限",人気,"馬番2桁"], ...},       // 複勝
    "3":"枠連(組番4桁)", "4":"馬連(組番4桁)", "5":"ワイド(組番4桁)",
    "6":"馬単(組番4桁)", "7":"3連複(組番6桁)", "8":"3連単(組番6桁)"
  }
}
```
組番は2桁ゼロ埋め馬番の連結（例："0608"=6番-8番のワイド）。
**将来combo_odds予約枠に対応する時、type=4/5/7がこのAPIだけで全部取れる**（追加調査不要）。

- 実装：`scraper/fetchers/b2_odds.py`（`fetch_odds()`, `merge_odds_into_race()`）
- テスト：`tests/test_b_shutuba.py`（3テスト、実サンプルで全通過確認済み）
- **未確認事項**：cURLにはブラウザのCookieが付いていたが、実装では最小ヘッダー
  （X-Requested-With + Referer）のみで組んである。**Cookie無しで本番稼働時に通るかは未検証**。
  弾かれたらCookie取得ステップの追加を検討。
