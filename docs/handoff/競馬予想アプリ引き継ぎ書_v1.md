## 1. アプリ概要

- **名称（仮）**: 週末3CARDS
- **一言**: 土日のメインレースを対象に、リスク度別の3枚カード（+確変4枚目）で買い目と一言分析を提示する、家族・友人共有型の競馬予想アプリ
- **利用者**: 家族・友人と共有（端末は iPhone / Android 混在）
- **プラットフォーム**: PWA（GitHub Pages 配信）想定。ネイティブは将来検討
- **開発の進め方**: 当面はこのチャット/Claude で作れるところまで作る。実行環境（Claude Code等）が整い次第そちらへ移行
- **コスト方針**: 運用月1,000円以内（GitHub Actions + Pages で実質0円を狙う構成）

## 2. これまでに確定した仕様

### 予想エンジン
- ハイブリッド（統計ロジック + LLM）。MVPは統計ロジック中心
- 買い目 = 統計ロジックで生成 / 分析コメント = LLM（キャラ口調）
- 当面はLLMコメントを運用者が手動生成して流し込み、API代ゼロ。将来API直結に切替可能な設計にする

### データ
- 無料データのスクレイピング自動化（netkeiba等・規約グレー承知）。将来 JRA-VAN 等の有料データ移行を視野
- 更新は当日朝、運用者が手動トリガー（ボタンポチ）で実行

### 対象・買い目
- 対象: 土日のメインレース全部（最大4〜6レース/週）。MVPもこの範囲
- 精度の定義: **的中率重視**（当てる楽しさを優先）。ただし運用者個人は回収率も狙いたい派
- 1カードあたり想定購入額: 500円前後で少点数（100円×5点程度）
- 券種: ワイド・馬連・3連複を使う。**単勝・複勝は使わない**
- カード内に複数券種をミックス
- 重視ファクター: ①過去走の時計・指数 ②血統・コース/馬場適性 ③騎手・厩舎傾向 ④オッズの歪み（過小評価馬検出）

### 成績集計
- 必須。予想師別・券種別に的中率と回収率を自動集計
- 成績表トップは「全予想師のカードを毎回すべて買った場合の累計収支」に一本化（合算の的中率のような曖昧な数値は出さない）
- マイナス収支も隠さず見せる方針（正直さ＝信頼性という思想）

## 3. キャラクター設計（4人の予想師）

各カードにキャラがいる。買い目は同一の予想モデルから **リスク許容度パラメータを変えて生成**し、
それぞれのキャラが「的中率×回収率のトレードオフ」の異なる立ち位置を担う。

| キャラ | リスク | 立ち位置 | 券種傾向 | 目標的中率(目安) |
|---|---|---|---|---|
| 🧑‍🎓 数理院生 ケイ | 低 | 的中率重視・堅実 | ワイド軸厚め+馬連 | 50%以上 |
| 👨‍👧 週末の馬券パパ 哲さん | 中 | バランス | 馬連+ワイド+3連複少点数 | 30%前後 |
| 👴 ベレー帽の大穴師 源さん | 高 | 一撃・大穴 | 3連複フォーメーション中心 | 10〜15% |
| 🎩 伝説の予想師 鳳(オオトリ) | 確変 | 上位互換・特別 | 全券種・掛け金1,000円で本数増 | 出現時のみ |

- キャラの分析コメントは各自の口調で書き分ける（ケイ=統計トーク、哲さん=家庭の匂い、源さん=ヤジ混じり、鳳=余裕）
- 詳細な性格・背景は別ファイル「予想師キャラクター外見設定_v1.md」参照
- キャラ絵は4人とも生成済み（アニメ塗り路線で採用）。モックに組み込み済み（後述 v7）

### 「妙味メーター」と鳳の降臨システム
- 各レースに **妙味メーター**（旧称「歪み度」から改名）を表示。オッズと当モデル評価の乖離（=期待値の旨み）を数値化した独自指標
- 妙味が閾値（サンプルでは80）を超えたレースにだけ **鳳が降臨**（確変演出）
- コンセプトの原点: 「重賞や朝イチの参加者が少ないレースはオッズが歪みやすく、そこを狙えば期待値が出るのでは」という運用者の仮説
- **重要な注意点（設計上の緊張関係）**: 「妙味が高い＝当たりやすい」ではない。妙味が高いレースは期待値は高いが的中率はむしろ下がりがち（人気薄を狙うため）。「的中率重視」の軸と「妙味レースを狙う」軸は引っ張り合う。この緊張をキャラ（ケイ⇔源さん）に担わせて解消している

---

## 4. 妙味メーターの計算式（未確定・Phase 2の宿題）

方向性のみ合意済み。実データを拾う中で確定させる。

```
妙味度 = f(
    モデル勝率とオッズ支持率の最大乖離,   # 過小評価馬がどれだけいるか
    期待値がプラスの買い目の本数,          # 旨みのある買い目の多さ
    レースの予測信頼度                     # 頭数の少なさ、実績データの揃い具合など
)
```

- 「旨み（期待値）」と「信頼度（自信）」は本来別成分。1本のメーターに混ぜている現状を、将来2軸に割る案もある（旨み度＋堅さ）
- 検証アイデア: 実績が貯まったら「妙味度80超のレースは実際に回収率◯%だった」という後方検証を見せられると、運用者の仮説そのものを検証でき、アプリの説得力が上がる

## 5. 予想ロジック v1（統計ベース・未実装）

各馬に4ファクターのスコアを付け、重み付き合成する。

1. **スピード指数**: 過去走タイムをコース・馬場差で補正した独自指数（直近数走の最高値・平均値）
2. **適性スコア**: 同コース・同距離・同馬場状態での過去成績
3. **人的スコア**: 騎手×コース成績、厩舎の勝率・調子
4. **オッズ乖離**: 合成スコア順位とオッズ順位のギャップ（過小評価馬の検出）→ 妙味メーターにも接続

- 合成スコア上位から ◎○▲△✕ の印を付与
- 印の組み合わせルールで、リスク許容度別に3（+1）カードの買い目を機械生成
- **重みは成績集計データで継続チューニング**。ここが精度向上の本丸

## 6. システム構成（月額0円構成の想定）

```
[GitHub Actions（手動トリガー: workflow_dispatch）]
   │ 土日朝、スマホからRunボタンをポチ
   ▼
[Pythonスクレイパー] 出馬表・過去走・オッズ・馬場状態を取得
   ▼
[予想ロジック] 4ファクター合成スコア → 印 → 買い目生成 → 妙味度算出
   ▼
[predictions.json] を生成しリポジトリにコミット
   ▼
[GitHub Pages（PWA）] が JSON を読んで表示
```

- 結果集計も同様: レース後にActionsで結果取得 → results.json 更新 → ダッシュボード反映
- スクレイピング注意: netkeiba等は規約グレー。アクセス間隔を十分空ける（1リクエスト数秒以上）、個人利用に留める、サイト構造変更で壊れる前提の設計にする

## 7. UIモックの現状（フロントの完成度）

最新版: **keiba-3cards-mock-v7.html**（単体HTML、キャラ絵4人をbase64で埋め込み済み）

実装済みの画面と機能:
- **レース一覧**: 土日別、各レースに妙味メーター、鳳降臨レースは金色ハイライト+「鳳 降臨」フラグ
- **レース詳細**: 競馬新聞式の◎○▲印（本命は赤）、枠番カラーの馬番チップ、妙味メーター、予想師カード（アバター+ニックネーム+想定的中率+払戻レンジ+買い目+キャラ口調のセリフ吹き出し）、鳳降臨時は確変バナー+シャイン演出
- **予想師名鑑**: 4人のプロフィール
- **成績**: 全カード購入時の累計収支サマリ、予想師別に的中バー・回収バー（損益分岐点の点線付き）・的中時平均払戻

技術メモ:
- データは `RACES` `CHARS` `STATS` の3つのJSライクなオブジェクトに集約。スクレイパーが生成する predictions.json をこの `RACES` 形式に合わせれば差し替えるだけで動く構造
- キャラ絵は `CHARS[id].img` に画像パス or data URI を入れると全画面反映。`avatarHtml()` ヘルパーが img/絵文字を自動切替
- CSS は和風（明朝体見出し + 芝の緑 + 赤ペン印）。デザインは今後さらに詰める余地あり
