## 1. 登録

- `config/edge_v1.json` が `main` の first-parent 履歴に初めて現れたコミットを登録コミット、その committer date を登録日時とする（EDGE_LOOP.md §3）。
- 登録日時より後に発走したレースだけを対象にする。
- この文書と設定が登録コミットとバイト単位で違えば、`spec_changed` として何も数えない。
- 券を決めるコード `research/edge_rules.py` は、登録コミットの版を Git から読んで使う。後でこのファイルが変わっても、この版の券は変わらない。
- 市場の確率の engine は、本線と同じものを使う。portfolio-shadow-v1 の登録コミット（`39a19ce`）の版の `research/market_audit.py`・`research/market_baseline.py` と、その設定（`config/market_baseline_v1.json`）を、portfolio-shadow-v1 と同じ方法で Git から読む。

## 2. 券の決め方

入力は、本線（portfolio-shadow-v1）と同じ「発走前の最終の凍結版」と、そのコミットの raw だけ。

1. **発走前の固定とオッズの時点**：`research/portfolio.py` の `portfolio_race` と同じ契約。次のどれかに当たるレースは除外する。
   - 発走前の版が無い
   - 凍結版のコミットに raw が無い
   - 3連複・単勝のオッズの時点が発走前と確かめられない
   - 単勝オッズの無い馬がいる
   - 単勝オッズのある馬が3頭未満
   - 3連複のオッズが無い
2. **市場の確率 q**：`market_trio`。払戻率は設定の `trio_payout`（0.75）、未収録の組は Harville の形で補い、1組あたりの上限を使う。本線と同じ。
3. **印の馬 M**：凍結版の `marks` で、印（◎・○・▲・△・✕）の付いた馬のうち、発走前の単勝オッズがある馬。
4. **候補**：3頭とも M に入る3連複の組。
5. **券**：候補のうち、q が大きい順に5組。q が同じなら、馬番を小さい順に並べた組の辞書順で前のもの。
   - 候補が5組に満たなければ、候補をすべて買う。
   - M が3頭に満たなければ見送る（投資0）。
6. 各100円。

## 3. レースごとに残す値と結果の契約

- 残す値：
  - 凍結版のコミットと frozen_at、Champion の model_id
  - 印の馬 M、券、`p_pre`（券の q の和）
  - 投資・払戻・的中
  - 同じレースの本線（`edge-v0`）の値：portfolio-shadow-v1 の記録の `x_out_2` の的中・`p_hit`・投資・払戻
- 結果の契約（portfolio-shadow-v1 と同じ）：
  - 3着内の同着（3連複の配当が2組以上）は除外する。
  - 3着内の馬に発走前の単勝オッズが無ければ除外する。
  - 的中なのに配当が見つからないレースは、払戻が分からないとして回収率から外す（的中には数える）。

## 4. 指標

- **主指標**：`H/E`（`H` は的中の数、`E` は `p_pre` の和）と、差 `(H − E)/n`。
- **この版では `p` を `p_pre` に固定する。**
  - EDGE_LOOP.md §4.2・§4.3 は、確定オッズの記録ができたら `p_final` を使うとしている。
  - この版の登録の時点では、確定オッズの記録（odds-live）がまだ無い。途中で `p_final` に切り替えると、判定の物差しが途中で変わる。そのため、この版の判定は最後まで `p_pre` で行う。
  - 確定オッズの記録ができたら、`p_final` での値を副指標として出す（判定には使わない）。
- **副指標**（報告だけ）：回収率、的中数、見送りの数、本線との的中の重なり。

## 5. 本線との入れ替えの判定（EDGE_LOOP.md §4.3 の経路1）

- **共通のレース**：この版と本線の両方の記録があるレース。
  - この版：`evaluated`（見送りを含む。見送りは `hit = 0`・`p = 0`・投資0）。
  - 本線：portfolio-shadow-v1 の記録が `evaluated` で、`x_out_2` が選べていて（`chosen`）、最適と確かめられている（`proven_optimal`）。
- **レースごとの差**：`d = (hit − p_pre)_v1 − (hit − p_pre)_v0`。
- **レースの解決**：登録後の各レースを、次の4つに分ける。
  - 共通：上の条件を満たす。
  - 対象外：
    - この版が除外された（§2-1・§3 の契約）。
    - または、本線の記録が評価済みで使えない（除外・`x_out_2` が選べていない・最適と確かめられていない・凍結版が違う）。
  - 待ち：この版の結果待ち、または本線の記録が無い・結果待ち。
  - 失敗：この版か本線の計算の失敗。
- **結果がそろわないレース**：
  - 開催日から14日たっても「待ち」のレースは、`result_unavailable` として対象外に確定する。確定した日と理由は台帳（`ledger.json`）に残す。
  - 後から結果や本線の記録が来ても、共通のレースに戻さない。
  - 「失敗」は、直るまで対象外にしない。
- **見る時点**：
  - 開催日を順に見て、「待ち」か「失敗」のレースが1つでもある開催日から先では、到達日を決めない。
  - 共通のレースの累計が 60・120・240・480 に初めて達した開催日を到達日とし、その開催日のレースは全部入れる。
  - そのため、到達日までのレースは、すべて共通か対象外に決まっている。結果がそろう前に判定することは無い。
- **計算する時点**：到達日から14日たってから計算する（結果の訂正を待つため。portfolio-shadow-v1 と同じ日数）。
- **区間**：開催日単位の bootstrap（開催日を復元抽出し、レースに等しい重み。10,000回、乱数の種 20261101）。`d` の平均の 99% 区間を、並べた値の50番目と9,950番目で取る（何度も見る分だけ厳しくする）。
- **基準**：区間の下限が 0 を超え、かつこの版の回収率が本線以上なら、「入れ替えの基準を満たした」とする。
  - 入れ替えそのものは、ユーザーに告知して行う（EDGE_LOOP.md §5）。
  - 入れ替えた後も、前の本線は試験の版として記録を続ける。
- **固定**：見る時点ごとに、最初に計算した結果を記録し、上書きしない。後の実行で計算し直した値が違えば警告にする。
- **中止**：480 の時点で基準を満たさなければ、試験の版を中止する。記録は残す。

## 7. 既知の限界

- **根拠が弱い。** H-027 は21レースの記述から立てた。区間は付けておらず、見た3通りの中で一番よく見えた形を版にしている。前向きでは差が縮む見込みが高い。
- **時間がかかる。** 共通のレース60は、今のペース（週末4〜6レース）でおよそ3か月かかる。
- **印は Champion の版による。** 予想ロジックの版が変われば、印も変わる。記録に model_id を残し、版が変わった時点を後から分けられるようにする。
- **`p_pre` は締め切りの1〜4時間前の市場。** 最後の動きで印の馬が売れていれば、`H/E` は確定オッズでの値より大きく出る。
- 3連複の未収録の組は推定で補っている（portfolio-shadow-v1 §9）。
