## 2. 仮説

- **H1（主）**：混合した3連複分布 T2 の 3連複 log loss は、市場の3連複分布 `market_trio` より小さい。
- **H2（副）**：混合した勝率 `p_mix` の勝ち馬 log loss は、単勝オッズの勝率 `p_mkt` より小さい。
- 先行する観察（採否の根拠にはしない）：これまでの前向き 11 レースでは、Champion の勝ち馬 log loss は市場より平均で悪い（`data/research/market_audit/paired_win_logloss.json`、有意性は未判定）。したがって b ≈ 0（モデルが価値を足さない）も十分あり得る。それを確かめるのがこの登録の目的。

## 3. 入力と契約

すべて発走前に固定した版を使う。満たさないレースは除外し、理由を記録する（訓練にも評価にも使わない）。
1〜5 と 7・8 は発走前に決まる「発走前の契約」、6 は結果が出てから決まる「結果の契約」。

1. **固定**：raw は「発走前に snapshot を最後に更新したコミット」の版（`research/market_audit.py` の `prerace_versions` の規則）。
2. **オッズの時点**：単勝・3連複とも `odds_timing_status = pre_race_verified`。`unknown`・`inconsistent`・`post_race_detected` は除外。9月の発走前コミットの無いレースや、時点の記録が無い 10/3・10/4 は「発走前を確認済み」と読み替えない。
3. **オッズの無い馬**：単勝オッズの無い出走馬が1頭でもいれば、取消と確認できない限りレースごと除外（その馬を外して正規化しない）。単勝オッズのある馬が3頭未満、3連複オッズが1件も無いレースも除外。
4. **確定オッズは使わない**：学習にも評価にも、発走前の凍結時点（だいたい 12〜14 時台）のオッズだけを使う。
5. **p_model**：`data/shadow/model_evaluation/race-performance-v1/races/{race_id}.json` の `probability.horses[]`（発走前の capture から作った勝率）。
   - 主：Champion（`p_champion`）。副：race-performance-v1（`p_challenger`。報告だけで採否には使わない）。
   - `status = evaluated`、`phase = forward`、`models.champion.capture.matched = true`・`fidelity = true` であること。
   - 単勝オッズのある全出走馬に p_model があること（印から外れた馬がいるレースは除外）。副の p_model が欠けるレースは、副の計算からだけ外す（主の計算には影響しない）。
   - 計算時点の `main` にある版を使う。個票に、そのファイルの blob SHA、`frozen_at`、`models.champion.model_id`、`config_hash`、`evaluation_config_hash`、`models.champion.snapshot.sha256`、p_model のある馬の数を残す。前回の出力から blob SHA が変わったレースは `p_model_source_changed` に列挙する（値は新しい版を使う。どちらの版を使うかを結果を見て選ばない）。
6. **結果**：`data/race_results.json` の `finish`（先頭が1着）。3着以内の組は `finish` の先頭3頭、勝ち馬は `finish[0]`。
   - `dividends` の 3連複が2件以上あるレース（3着内の同着）は除外（`dead_heat_top3`）。
   - 1着の同着は結果データで判別できないので `finish[0]` を勝ち馬とする（§11 の既知の限界）。
   - 3着以内の馬に発走前の単勝オッズが無いレースは除外（`top3_horse_without_prerace_odds`）。
7. **開催日**：`race_id` の先頭8桁（JST の日付）。同じ日の別の競馬場のレースは同じ開催日。
8. **発走時刻**：開催日＋`post_time`（JST）。

## 4. モデル

計算はすべて倍精度で行い、丸めは出力のときだけ。`eps = 1e-12`。

### 4.1 勝率の混合

`p_mix(i) = exp(a·log p_mkt(i) + b·log p_model(i)) / Σ_j exp(a·log p_mkt(j) + b·log p_model(j))`

- `p_mkt`：単勝オッズの逆数を、単勝オッズのある全出走馬で正規化したもの（登録コミットの `win_probs`）。
- `p_model`：単勝オッズのある全出走馬に限って合計 1 に正規化し、`max(p, eps)` にしてから log を取る。
- 格子：`a = i/50`（i = 0…150、0〜3）、`b = j/50`（j = −100…100、−2〜2）。b ≤ 0 も許す（モデルが逆向きに効く・効かない可能性を排除しない）。
- 目的関数：訓練レースの勝ち馬の `−log max(p_mix(勝ち馬), eps)` の平均。訓練レースは `race_id` の昇順で足す。
- 選び方：目的関数の最小値を `L*` とし、`L ≤ L* + 1e-12` の格子点をすべて同点とする。同点の中から、`|b|` が小さい → `|a−1|` が小さい → `a` が小さい → `b` が小さい、の順で1点に決める。

### 4.2 3連複の分布

- **市場の分布** `market_trio`：登録コミットの `market_trio(race, runners, payout, shape, use_cap)`。主の補い方は 払戻率 0.75・配る形 `harville_trio(p_mkt)`・1組の上限あり。配る形には `p_mkt` だけを使い、`p_mix` や p_model は使わない（市場の分布にモデルの情報を入れない）。未収録組の確率は推定であって、市場の真の確率ではない。
- **T1**：`harville_trio(p_mix)`。素の Harville（＝素の Plackett–Luce）。Harville の偏りを補正したものではない。
- **T2**：`w·market_trio + (1−w)·T1`。w = 1 なら `market_trio` そのものになるので、モデルが価値を足さなければ T2 は市場に戻る。
- 格子：`w = k/20`（k = 0…20）。
- 目的関数：訓練レースの `−log max(T2(実際の組), eps)` の平均。T1 は、その開催日のために当てはめた a・b で、訓練レースそれぞれについて作り直す（訓練レースの当時の a・b ではない）。
- 選び方：最小値を `L*` とし、`L ≤ L* + 1e-12` の w を同点とする。同点なら大きい w（市場寄り）。

## 5. 当てはめ（walk-forward）

- 開催日 d ごとに、d より前の開催日の、契約を満たし結果のある全レースを訓練に使い、a・b を当てはめ、次に w を当てはめる（窓は拡大していく。登録前のレースも訓練には使う）。
- 訓練レースが 10 未満の開催日は評価しない（その日のレースは `insufficient_training` として評価から外す。後の開催日の訓練には使う）。
- 評価レースの結果を、そのレースや同じ開催日の当てはめに使うことはない。
- 実装は、毎回すべての開催日を最初から計算し直す。

## 6. 評価と採否

### 6.1 対象と指標

- **対象**：発走時刻が `registered_at` より後で、契約を満たし、結果が確定し、§5 で評価する開催日のレース。
- **主指標**：レースごとの `D_r = trio_logloss(T2) − trio_logloss(market_trio)`（`trio_logloss = −log max(P(実際の組), eps)`）。点推定は対象の全レースでの `D_r` の単純平均（レースに等しい重み）。
- **副指標**（報告するが採否には使わない）：
  - 勝ち馬 log loss `p_mix − p_mkt`
  - 3着内 Brier `T2 − market_trio`（各馬の3着内確率は分布の周辺確率。PR-B の `top3_brier` と同じ定義）
  - `trio_logloss(T1) − trio_logloss(harville_trio(p_mkt))`（Harville の中でモデルが情報を足すか）
  - 副の p_model（race-performance-v1）で §4・§5 を同じ手順で回した結果

### 6.2 判定の区間

- **数え方**：区間は「発走前の契約（§3）を満たし、発走時刻が `registered_at` より後で、§5 で評価する開催日のレース」（結果待ちを含む）の累計で決める。結果の有無や中身で区間がずれないようにするため。
- **判定の時点**：その累計が初めて 100 以上になった開催日の終わり（その開催日のレースはすべて含める。開催日を途中で切らない）。100 に届かないまま 2027-06-30 を過ぎたら、開催日が 2027-06-30 以前のレースすべてで判定する。
- 区間のレースのうち、結果の契約（§3.6）で外れるもの、区間の最後の開催日から 14 日たっても結果が無いもの（`result_unavailable`）を除いた残りが、判定に使う評価レース。判定はこの 14 日の後に1回だけ計算する。
- **チェックポイント**：同じ累計が初めて 30・60 以上になった開催日の終わり（同じく開催日を切らない）。報告だけで採否は判断しない。害による打ち切りは無い（observe-only でお金を使わない）。チェックポイントで条件を緩めたり、判定を早めたりしない。

### 6.3 開催日単位の bootstrap

- 判定の区間の評価レースのある開催日を昇順に並べる（数を `N_day` とする）。
- `rng = random.Random(20261019)`（Python 標準の Mersenne Twister）。10000 回、各回 `rng.randrange(N_day)` を `N_day` 回引いて開催日を復元抽出する（同じ開催日が2回出たら、その日の全レースを2回数える）。
- 各回の統計量は、抽出した開催日の全レースの `D_r` の合計 ÷ そのレース数（レースに等しい重み。点推定と同じ定義）。
- 区間は percentile 法。10000 個の統計量を昇順に並べ、下限は 250 番目、上限は 9750 番目の値（1 から数える）。

### 6.4 採否の判定

判定の時点で、次の3つをすべて満たせば **採用**。

1. 主指標の点推定 < 0
2. §6.3 の bootstrap の上限 < 0
3. §7 の 18 通りすべてで、主指標の点推定 < 0

- **判定不能**：判定の区間の評価レースが 30 未満、または `N_day` が 10 未満なら、bootstrap の結果にかかわらず採否を判定しない（少ない標本で区間が狭く出ても自動で採用しない）。判定不能は不採用と同じ扱い（市場だけの基準線を使い続ける）で、v1 はそこで終わる。続けるなら v2 を登録する。
- **採用の意味**：PR-D 以降の shadow とチャット参考券の確率エンジンとして使ってよい。アプリ・本番への反映は別途ユーザーの承認が要る。
- **不採用なら**：市場だけの基準線を使い続ける。

## 7. 未収録組の補い方への感度（PR #41 レビューの申し送り）

- `market_trio` は、1000倍超などで収録されていない組の確率を推定で補っている。「未収録の組のオッズは収録の最大値以上」は**収集仕様で証明されていない仮定**。
- 18 通り：払戻率 {0.725, 0.75, 0.775} × 配る形 {`harville_trio(p_mkt)`, `harville_trio(p_mkt, (0.81, 0.65))`, 一様（全組に 1/組数）} × 1組の上限 {あり, なし}。主の補い方はこのうちの1つ（0.75・harville・あり）。
- 補い方 v ごとに、パイプライン全体をその補い方で作り直す：
  - a・b・T1 は 3連複の分布に依らないので、主の計算と同じ値。
  - `market_trio_v` を補い方 v で作り、w を §4.2・§5 と同じ格子・同点の決め方で、**訓練も評価も同じ v の `market_trio_v` を使って**開催日ごとに当てはめ直す（`w_v`）。
  - `T2_v = w_v·market_trio_v + (1−w_v)·T1`、`D_r^v = trio_logloss(T2_v) − trio_logloss(market_trio_v)`。
  - 対象レースは §6.1 の主の対象と同じ集合（補い方で増減させない）。点推定は §6.1 と同じ単純平均。bootstrap は主の補い方だけで行う。
- 補い方の中から有利なものを選ぶことはしない。条件3は 18 通り**すべて**で点推定 < 0 を求める。
- 登録時点の 12 レースでは、`market_trio` の平均 3連複 log loss は 4.720〜4.775、どの補い方でも Harville・discounted Harville より小さかった（PR-B の `summary.sensitivity`。12 レース・有意性は未判定。採否の根拠ではない）。

## 8. 過去データの整備方針

- 過去レースの確定着順と**確定オッズ**は集められるが、確定オッズは発走前の凍結時点のオッズと別物で、p_model も過去レースについては存在しない。
- そのため、**a・b・w の当てはめには過去データを使わない**（前向きに積み上がるレースだけで walk-forward）。
- 過去データは、市場の構造の研究（例：discounted Harville の λ、未収録組の分布、払戻率）にだけ使ってよい。その場合も、時点の違い（確定オッズ vs 凍結時点）を別の課題として明記し、取得は別の棚卸し PR で行う。

## 9. 変更規則・禁止事項

- 登録後に、この文書・設定の式・格子・同点の決め方・許容差・閾値・チェックポイント・bootstrap・p_model の選び方を変えない。変えるなら v2 として別に登録し、v1 の評価は続ける。

## 10. 実装の約束（PR-C2）

- `research/market_mix.py` で、この文書と設定のとおりに当てはめと評価を実装する。出力は `data/research/market_mix/` だけ。
- 入力はすべて発走前に固定されているので、実装が最初の評価レースの後になっても、評価は登録した仕様どおりに再現できる。実装は登録した仕様を変えず、仕様に無い選択をしない（§冒頭）。
- 出力には、`registration.json`（§1 を Git から導出したもの）、各開催日の a・b・w（18 通りの `w_v` も）、訓練レースの一覧、除外の理由、主・副指標、bootstrap の区間と `N_day`、感度 18 通りの結果、判定の状態（`collecting`・`checkpoint_30`・`checkpoint_60`・`adopted`・`not_adopted`・`undecidable`）を残す。
- 個票には §3.5 の p_model の出どころを残す。

## 11. 既知の限界

- 訓練レースが少ない（登録時 11）。a・b・w の推定は不安定で、評価の前半は市場寄り（w が大きい）になりやすい。
- w は、同じ訓練レースで当てはめた a・b の T1 で選ぶので、訓練では T1 が実際より良く見え、w が小さめ（モデル寄り）に出やすい。評価は訓練に使っていないレースで行うので、この偏りは採用を甘くする方向には働かない。
- p_model は Champion の現行モデルで、今後 Champion 自体が変わると、それ以降のレースの p_model は別物になる。区間は `(models.champion.model_id, config_hash)` の組が変わった開催日で分け、区間ごとの値も併記する（採否の判定は全体で行う）。
- 1着の同着は結果データで判別できない（勝ち馬 log loss の副指標にだけ影響する）。
- 3連複の分布の補い方は近似。感度の条件（§6.4 の 3）で守る。
