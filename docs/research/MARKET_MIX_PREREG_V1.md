変えたくなったら v2 として別に登録する。予想・正式成績・UI・Champion・scenario-frame/v1 は変えない。

## 0. 位置づけ

- #39 の案1：「市場を土台に、能力モデルで補正する」。PR-A（市場オッズ監査）と PR-B（市場だけの基準線）の上に作る。
- 問い：**能力モデルの確率を市場の確率に混ぜると、市場だけより「どの3頭が3着以内に入るか」をよく当てられるか。**
- 当たりやすさ（的中率）や回収率ではなく、確率の当たり方（proper な指標）で判定する。買い目の組み方・見送りは PR-D の担当で、ここでは決めない。

## 2. 仮説

- **H1（主）**：混合した3連複分布 T2 の 3連複 log loss は、市場の3連複分布 `market_trio` より小さい。
- **H2（副）**：混合した勝率 `p_mix` の勝ち馬 log loss は、単勝オッズの勝率 `p_mkt` より小さい。
- 先行する観察（採否の根拠にはしない）：これまでの前向き 11 レースでは、Champion の勝ち馬 log loss は市場より平均で悪い（`data/research/market_audit/paired_win_logloss.json`、有意性は未判定）。したがって b ≈ 0（モデルが価値を足さない）も十分あり得る。それを確かめるのがこの登録の目的。

## 3. 入力と契約

すべて発走前に固定した版を使う。満たさないレースは除外し、理由を記録する（訓練にも評価にも使わない）。

1. **固定**：raw は「発走前に snapshot を最後に更新したコミット」の版（`research/market_audit.py` の規則）。
2. **オッズの時点**：単勝・3連複とも `odds_timing_status = pre_race_verified`。`unknown`・`inconsistent`・`post_race_detected` は除外。9月の発走前コミットの無いレースや、時点の記録が無い 10/3・10/4 は「発走前を確認済み」と読み替えない。
3. **オッズの無い馬**：単勝オッズの無い出走馬が1頭でもいれば、取消と確認できない限りレースごと除外（その馬を外して正規化しない）。
4. **確定オッズは使わない**：学習にも評価にも、発走前の凍結時点（だいたい 12〜14 時台）のオッズだけを使う。
5. **p_model**：`data/shadow/model_evaluation/race-performance-v1/races/{race_id}.json` の `probability.horses[]`（発走前の capture から作った勝率）。
   - 主：Champion（`p_champion`）。副：race-performance-v1（`p_challenger`。報告だけで採否には使わない）。
   - `status = evaluated`、`phase = forward`、Champion の capture が `matched`・`fidelity` であること。
   - 単勝オッズのある全出走馬に p_model があること（印から外れた馬がいるレースは除外）。

## 4. モデル

### 4.1 勝率の混合

`p_mix(i) ∝ exp(a·log p_mkt(i) + b·log p_model(i))`

- `p_mkt` は単勝オッズの逆数を正規化したもの。
- a・b は訓練レースの勝ち馬の平均 −log p_mix を最小にする値。格子探索（a ∈ [0, 3]、b ∈ [−2, 2]、刻み 0.02）。同点なら |b| が小さい方、次に |a−1| が小さい方。
- b ≤ 0 も許す（モデルが逆向きに効く・効かない可能性を排除しない）。

### 4.2 3連複の分布

- **T1**：`harville(p_mix)`。素の Harville（＝素の Plackett–Luce）。Harville の偏りを補正したものではない。
- **T2**：`w·market_trio + (1−w)·T1`。w は訓練レースの平均 3連複 log loss を最小にする値（0〜1、刻み 0.05。同点なら市場寄りの大きい w）。w = 1 なら `market_trio` そのものになるので、モデルが価値を足さなければ T2 は市場に戻る。
- `market_trio` は PR-B の主の補い方（払戻率 0.75、未収録組には Harville の形、1組の上限あり）。全組で合計 1。

## 5. 当てはめ（walk-forward）

- 開催日ごとに、その開催日より前の、契約を満たす全レースで a・b・w を当てはめ直す（窓は拡大していく。登録前のレースも訓練には使う）。
- 訓練レースが 10 未満の開催日は評価しない。
- 評価レースの結果を、そのレースの当てはめに使うことはない。

## 6. 評価と採否

- **対象**：登録日時より後に発走し、契約を満たし、結果が確定したレース。
- **主指標**：同じレースで対にした `trio_logloss(T2) − trio_logloss(market_trio)` の平均。
- **副指標**（報告するが採否には使わない）：
  - 勝ち馬 log loss `p_mix − p_mkt`
  - 3着内 Brier `T2 − market_trio`
  - `trio_logloss(T1) − trio_logloss(harville(p_mkt))`（Harville の中でモデルが情報を足すか）
  - 副の p_model（race-performance-v1）で同じ手順を回した結果
- **チェックポイント**：評価レース 30・60 では報告だけ。採否は判断しない。害による打ち切りは無い（observe-only でお金を使わない）。
- **採否の判定**：評価レース 100、または 2027-06-30 の早い方で、次の3つをすべて満たせば採用。
  1. 主指標の差の平均 < 0
  2. 開催日単位の bootstrap（同じ日の全レースを一緒に再抽出。10000 回、seed 20261019）の 95% 区間の上限 < 0
  3. 未収録組の補い方 18 通り（払戻率 0.725/0.75/0.775 × 形 harville/discounted_harville/uniform × 上限あり/なし）のすべてで、差の平均 < 0
- **採用の意味**：PR-D 以降の shadow とチャット参考券の確率エンジンとして使ってよい。アプリ・本番への反映は別途ユーザーの承認が要る。
- **不採用なら**：市場だけの基準線を使い続ける。

## 7. 未収録組の補い方への感度（PR #41 レビューの申し送り）

- `market_trio` は、1000倍超などで収録されていない組の確率を推定で補っている。「未収録の組のオッズは収録の最大値以上」は**収集仕様で証明されていない仮定**。
- `research/market_baseline.py` が 18 通りの補い方で `market_trio` の指標を計算する（`summary.sensitivity`）。登録時点の 12 レースでは、`market_trio` の平均 3連複 log loss は 4.720〜4.775、どの補い方でも Harville・discounted Harville より小さかった（12 レース・有意性は未判定。採否の根拠ではない）。
- 採否の条件 3 は、この感度の範囲で結論が変わらないことを求める。

## 8. 過去データの整備方針

- 過去レースの確定着順と**確定オッズ**は集められるが、確定オッズは発走前の凍結時点のオッズと別物で、p_model も過去レースについては存在しない。
- そのため、**a・b・w の当てはめには過去データを使わない**（前向きに積み上がるレースだけで walk-forward）。
- 過去データは、市場の構造の研究（例：discounted Harville の λ、未収録組の分布、払戻率）にだけ使ってよい。その場合も、時点の違い（確定オッズ vs 凍結時点）を別の課題として明記し、取得は別の棚卸し PR で行う。

## 9. 変更規則・禁止事項

- 登録後に、この文書・設定の式・格子・閾値・チェックポイント・p_model の選び方を変えない。変えるなら v2 として別に登録し、v1 の評価は続ける。
- 評価レースの結果を見てから、主の p_model を副と入れ替えない。
- 除外したレースを後から評価に戻さない。除外の理由はすべて記録する。
- 結果の確定した 30・60 のチェックポイントで、採否の条件を緩めない。

## 10. 実装の約束（PR-C2）

- `research/market_mix.py` で、この文書と設定のとおりに当てはめと評価を実装する。出力は `data/research/market_mix/` だけ。
- 入力はすべて発走前に固定されているので、実装が最初の評価レースの後になっても、評価は登録した仕様どおりに再現できる。ただし実装は登録した仕様を変えない。
- 出力には、各開催日の a・b・w、訓練レースの一覧、除外の理由、主・副指標、bootstrap の区間、感度 18 通りの結果を残す。

## 11. 既知の限界

- 訓練レースが少ない（登録時 11）。a・b・w の推定は不安定で、評価の前半は市場寄り（w が大きい）になりやすい。
- p_model は Champion の現行モデルで、今後 Champion 自体が変わると、それ以降のレースの p_model は別物になる。Champion が変わった場合は、その日から先を別の区間として報告する（採否の判定は、変更前と後を混ぜた全体で行うが、区間ごとの値も併記する）。
- 3連複の分布の補い方は近似。感度の条件（§6 の 3）で守る。
