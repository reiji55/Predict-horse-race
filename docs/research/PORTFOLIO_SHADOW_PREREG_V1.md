## 0. 位置づけ

- #39 の (E)。PR-D（`research/portfolio.py`、portfolio-v1）の組み方を、登録後のレースで前向きに記録し、確率の当たり方を確かめる。
- **問い：市場だけの確率（engine）で組んだ3連複5点の「的中確率」は、実際の的中の頻度と合っているか（校正されているか）。**
- この問いを選ぶ理由：
  - 市場だけの engine では、どの組み方でも期待回収が構造上ほぼ払戻率（約 0.75）になる（PR-D）。期待値で組み方の優劣は決まらない。
  - 組み方の違いは「的中確率」と「軸 X が外れたときに残る確率」の交換である。その数字を人に示して使うには、数字が実際と合っていることが前提になる。
  - チャットの参考券は、この確率を目安として示している。その表示を続けてよいかを、この登録で決める。
- 回収率（ROI）は外れ値に支配され、このレース数では判定できないので、報告だけにする。

## 2. 対象と組み方

- **対象のレース**：発走時刻（`race_id` の日付＋`post_time`、JST）が `registered_at` より後で、§3 の発走前の契約を満たすレース。
- **組み方**：凍結した `config/portfolio_v1.json` の `top_prob`・`x_out_2`・`exposure_cap_3`。
  - `cap3_x_out_2` は5点では `exposure_cap_3` と同じ組になる（PR-D で確認）ので、評価からは外す（記録だけ残す）。
  - 組と X・測る値は、凍結した `research/portfolio.py` の `portfolio_race` で計算する。
- **組は発走前の入力だけで決まる**：入力はすべて発走前に固定した版（§3）で、組み方は凍結したコードによる決定的な計算である。そのため、計算が発走後になっても、発走前に決めた組と同じになる。人が選ぶ余地は無い。
- **最適と示せなかった組**：`proven_optimal: false`（探索の上限による打ち切り）の組は、そのレースのその組み方の評価から外し、理由（`not_proven_optimal`）を残す。
- **制約を満たせない組**：`infeasible` の組は、そのレースのその組み方の評価から外し、理由を残す。

## 3. 入力と契約

**発走前の契約**（どれも発走前に決まる。満たさないレースは対象にしない）：

1. raw は「発走前に snapshot を最後に更新したコミット」の版（`research/market_audit.py` の規則）。
2. 単勝・3連複とも `odds_timing_status = pre_race_verified`。
3. 単勝オッズの無い出走馬がいない（取消と確認できない限りレースごと除外）。単勝オッズのある馬が3頭以上。3連複オッズが1件以上。

**結果の契約**（結果が出てから決まる）：

4. 結果は `data/race_results.json` の `finish`（先頭が1着）。3着以内の組は先頭3頭。
5. `dividends` の 3連複が2件以上（3着内の同着）なら除外（`dead_heat_top3`）。
6. 3着以内の馬に発走前の単勝オッズが無ければ除外（`top3_horse_without_prerace_odds`）。
7. 的中は「3着以内の組が5点のどれかと一致」。

開催日は `race_id` の先頭8桁（JST の日付）で、同じ日の別の競馬場も同じ開催日とする。

## 4. 指標

レース r・組み方 s ごとに、`hit_rs ∈ {0, 1}`（的中）と `p_rs`（`portfolio_race` の `p_hit`、主の補い方での的中確率）を記録する。

- **主指標**：`top_prob` の `C = (Σ_r (hit_r − p_r)) / n`（レースに等しい重み。実際の的中率 − 予測した的中確率の平均）。
- **副指標**（報告だけで、判定には使わない）：
  1. `x_out_2`・`exposure_cap_3` の同じ `C`。
  2. X の校正：`(Σ_r (1[X が3着内] − P(X が3着内))) / n`。
  3. X が3着外だったレースでの、実際の的中率と予測した条件付き的中確率（`p_hit_given_x_out`）の平均。組み方ごと。
  4. 回収：組み方ごとの的中数・投じた額・払戻の合計・回収率、レースごとの払戻の標準偏差。
  5. scenario-frame/v1 の正式に有効な記録があるレースでの、`top_prob` と v1 の的中の対比（両方が的中・片方だけ・両方外れの数）。
  6. 未収録組の補い方 18 通りでの `p_hit` の幅（`p_hit_variants`）の平均。
  7. 主指標の、`p_rs` を18通りの最小値・最大値に置き換えたときの値（尾部の補い方への感度）。

## 5. 区間・bootstrap・判定

### 5.1 区間

- **数え方**：発走前の契約を満たす対象のレース（結果待ちを含む）の累計で区間を決める。
- **チェックポイント**：累計が初めて 30・60 以上になった開催日の終わり（開催日を途中で切らない）。報告だけで、判定はしない。
- **判定の時点**：累計が初めて 100 以上になった開催日の終わり。100 に届かないまま 2027-06-30 を過ぎたら、開催日が 2027-06-30 以前のレースすべて。
- 区間のレースのうち、結果の契約で外れるもの、区間の最後の開催日から 14 日たっても結果が無いもの（`result_unavailable`）を除いた残りが評価レース。判定はこの 14 日の後に1回だけ計算する。
- 主指標の評価レースは、そのうち `top_prob` が `chosen` かつ `proven_optimal` のもの。

### 5.2 開催日単位の bootstrap（主指標）

- 評価レースのある開催日を昇順に並べる（数 `N_day`）。
- `rng = random.Random(20261021)`。10000 回、各回 `rng.randrange(N_day)` を `N_day` 回引いて開催日を復元抽出する。
- 各回の統計量は、抽出した開催日の全レースの `(hit − p)` の合計 ÷ そのレース数。
- 区間は percentile 法。昇順の 250 番目を下限、9750 番目を上限とする（1 から数える）。

### 5.3 判定

判定の時点で、次の順に1つに決める。

1. **判定不能**（`undecidable`）：評価レースが 30 未満、または `N_day` が 10 未満。
2. **校正が取れていない**：
   - `over`：bootstrap の上限 < 0。予測した的中確率が、実際より高い。
   - `under`：下限 > 0。予測した的中確率が、実際より低い。
3. **校正が取れている**（`calibrated`）：区間が 0 を含み、かつ `|C| ≤ 0.05`。
4. **決められない**（`inconclusive`）：上のどれでもない（区間が 0 を含むが `|C| > 0.05`）。

**判定の意味**：

- `calibrated`：チャットの参考券で、engine の的中確率を「市場の確率による目安」として、区間とあわせて示してよい（的中の保証ではない）。
- それ以外：参考券では的中確率を数値で示さず、「市場の確率が実際と合っていることは未確認」と書く。
- 組み方の既定（`top_prob` か、制約のある組み方か）は、この判定では決めない。副指標の報告をもとに、ユーザーが選ぶ。
- アプリ・本番への反映には、別途ユーザーの承認が要る。

## 6. 記録と不変性

- 判定が確定したら、入力（評価レースの一覧、各レースの状態・固定した raw のコミット・使った結果）と出力（判定と全集計）を digest つきで `decision.json` に1回だけ書き、上書きしない。
- 以後は毎回計算し直して digest を比べる。違えば警告にする。
- 30・60・100 の到達日は、最初に決まった値で台帳（`ledger.json`）に残し、上書きしない。後から違えば `events` に追記して警告にする。

## 7. 変更規則・禁止事項

- 登録後に、この文書・設定、凍結した参照コードと設定を、v1 の計算に使う形で変えない。変えるなら v2 として別に登録し、v1 の評価は続ける。
- 評価レースの結果を見てから、主の組み方・指標・閾値・seed を入れ替えない。
- 除外したレースを後から評価に戻さない。除外の理由はすべて記録する。
- チェックポイントで判定を早めたり、条件を緩めたりしない。
- market-mix-v1 が採用されても、v1 の engine は市場だけのまま続ける（混合の engine を使うなら v2 として別に登録する）。

## 9. 既知の限界

- engine は市場だけで、モデルの優位性を含まない。期待回収で組み方の優劣は決まらない（§0）。
- 3連複の未収録組（1000倍超など）は推定で補っている。市場の真の確率ではない。感度は副指標 6・7 で見る。
- 展開（ペース・脚質）のデータは無い（`pace_unknown`）。X が外れる場合の条件付けは確率の上の計算で、展開の予測ではない。
- `x_out_2` は X 以外の馬への集中を防がない。各馬の集中を抑えるのは `exposure_cap_3` だけである。
- 主指標は `top_prob` の5点の確率の和（およそ 0.19）の校正なので、100 レースでも区間は ±0.08 程度になる見込みで、`inconclusive` もあり得る。
- scenario-frame/v1 の記録は 12:30 前後の版のオッズで作られている。ここでは、どの組み方も発走前に固定した最終版の確率で測る。
