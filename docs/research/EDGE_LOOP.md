## 0. 目的と経緯

- プロジェクトの目的：**市場（オッズ）が低く見ている組、つまり本当の当たる確率が市場の確率より高い組を、発走前に見つけ続ける仕組みを作る。** ユーザーの言葉（2026-10-31 のチャット）：「初めからその条件に該当する予想を取得し続けるロジック、システムを構成したくて今悪戦苦闘してる感じだから、そこを探すのがこのプロジェクトのミッションです」。
- 同じ日の指示：「市場入替の予測を積んでいって、傾向とかパターンとか結果を分析し続けていくなかで、回収率を上げられるであろう予兆とか、ロジックが見つけられたら、随時形を変えていっていいよ。重要な変更とかあるなら告知して欲しいけど。基本的には勝手に補正していっていい」。
- この文書は、その「随時形を変える」を偶然に振り回されずに進めるための決まりを書く。強化学習の「やってみる → 結果を見る → やり方を直す」の型を、検証できる手続きにしたもの。
- 出発点：市場の確率だけで組む限り、期待回収は構造上ほぼ払戻率（約 0.75）になる（[PORTFOLIO.md](PORTFOLIO.md)、[PORTFOLIO_SHADOW_PREREG_V1.md](PORTFOLIO_SHADOW_PREREG_V1.md) §0）。市場より確率の高い組を見つける材料は、まだ立証されていない（Issue #39）。

## 2. 学習ループの型と原則

| 強化学習の言葉 | ここでの意味 |
|---|---|
| 行動 | 発走前に、版の手順で券を決める |
| 報酬 | 的中と払戻。判断には主に「確定オッズの見込みより何回多く当たったか」を使う（§4） |
| やり方の更新 | 傾向が見えたら新しい版を作り、試験の版として並走させる。基準（§4.3）を満たしたら本線と入れ替える |
| 探索と活用 | チャットで出す参考券（本線）は1つ。試験の版は記録だけ |

原則：

1. **変えるのは自由、成績は変えた後で数える。** 版の成績は、その版の登録（§3）より後に発走したレースだけで数える。過去のデータで良く見えたことは「試す理由」であって、成績ではない（[reflections/README.md](reflections/README.md) の原則1と同じ考え方）。
2. **試した版は全部残す。** 中止した版も、登録・中止の日時と理由を台帳（§10）に残す。何回試したかが分からないと、偶然の当たりを見抜けない。
3. **判断を回収率だけで決めない。** 3連複の回収率は1回の大当たりで大きく動く（§6.1）。
4. **並走させる試験の版は、同時に3つまで。** 比べる版が多いほど、偶然に良く見える版が出やすい。
5. **入れ替えの基準は版を登録するときに決めて書き、後から緩めない。** この文書の基準を後で変えても、変える前に登録した版には前の基準を使う。
6. **過去のデータで探すときも、探す期間と確かめる期間を先に分ける**（§4.3 の経路2）。

## 3. 版

- 版は、発走前に固定した入力だけから、決定的に券を決める手順。人が選ぶ余地を残さない。
- 登録：版ごとの設定ファイルが `main` の first-parent 履歴に初めて現れたコミットを登録コミット、その committer date を登録日時とする（market-mix-v1・portfolio-shadow-v1 と同じ方式）。設定ファイルの置き場所と記録のコードは、最初の試験の版と一緒に作る。
- **`edge-v0`（チャットでの呼び名：市場入替 v0）**
  - 中身：`config/portfolio_v1.json` の `x_out_2`。市場だけの3連複の分布（`research/market_baseline.py` の `market_trio`、払戻率 0.75、未収録の組は Harville の形で補う）を使い、3着内の確率が最も高い馬 X を含まない組を最低2点入れる条件のもとで、5点の確率の和を最大にする。各100円の5点で、見送りは無い。
  - 登録：portfolio-shadow-v1 の登録（`39a19ce`、2026-10-21 15:52:40 JST）。
  - 前向きの記録：portfolio-shadow-v1 が `x_out_2` として毎レース自動で残している（`data/research/portfolio_shadow/races/`）。入力は発走前の最終の凍結版（同 §3）。
  - チャットで出す券は、出す時点の凍結版から同じ手順で計算する。最終版とはオッズの時刻が違うので、券が変わることがある（10/31 の2レースは同じだった）。チャットで出した券を発走前に記録する仕組みは次の PR で作る（§8.1）。それまでは、チャットで出した券そのものは検証できない参考とし、`edge-v0` の成績は portfolio-shadow-v1 の記録で数える。
- 参考券で的中確率を数値で示すかは、portfolio-shadow-v1 の判定（同 §0・§5.3）に従う。判定までは市場の確率による目安として示し、実際と合っているかは確かめられていないと添える。

## 4. 測り方と入れ替えの基準

### 4.1 レースごとに残す値

| 値 | 意味 |
|---|---|
| `hit` | 的中（0/1）。3着内の同着は portfolio-shadow-v1 と同じく除外する |
| `p_pre` | その版が見た発走前の市場での、券の確率の和 |
| `p_final` | 確定オッズに同じ engine を使ったときの、券の確率の和（確定オッズの記録ができてから。§8.1） |
| `stake`・`payout` | 投資と払戻 |

### 4.2 指標

- **主指標**：確定オッズの見込みに対する的中の比 `H/E`（`H` は的中の数、`E` は `p_final` の和）と、差 `(H − E)/n`。確定オッズの記録ができるまでは `p_pre` で代用し、そう明記する。
- 目安：券の配当は市場の確率 p に対しておよそ 0.75/p 倍なので、`H/E` がおよそ 1/0.75 ≒ **1.33 を超えると回収率が100%を超える**（券ごとの比がそろっている場合の目安）。
- **副指標**（報告だけ）：回収率、的中数、X が3着を外れたときの成績、`p_pre` と `p_final` の差。

### 4.3 本線の入れ替え

試験の版が次のどちらかを満たしたら、本線と入れ替える。入れ替えた後も、前の本線は試験の版として記録を続ける。以下の `p` は `p_final`（記録ができるまでは `p_pre`）。

- **経路1（前向きの記録だけ）**：試験の版と本線の両方の記録があるレースで、レースごとの差 `d = (hit − p)_試験 − (hit − p)_本線` の平均を見る。見るのは、共通のレースが 60・120・240・480 に初めて達した開催日の終わりだけ。開催日単位の bootstrap の 99% 区間（何度も見る分だけ厳しくする）の下限が 0 を超え、回収率も本線以上なら入れ替える。
- **経路2（過去データと前向きの記録）**：過去のデータ（確定オッズと結果）を受け取った時点で、中身を見る前に「探す期間」と「確かめる期間」を決めて台帳に書く。版は探す期間だけで作り、確かめる期間では1回だけ測る。次の3つをすべて満たしたら入れ替える。
  - 確かめる期間で、`H/E` の 95% 区間の下限が 1 を超える。組み合わせのオッズ表が無いデータでは `H/E` を計算できないので、同じレースの本線との回収率の差の 95% 区間の下限が 0 を超えることで代える。
  - 確かめる期間で、回収率の点推定が本線を上回る。
  - 登録後の前向きの記録が30レース以上あり、`d` の 95% 区間の上限が 0 を超える（本線より明らかに悪くはない）。
- 見送り（pass）を含む版もありうる（Issue #39）。見送ったレースは、投資0・`hit = 0`・`p = 0` として数える。

## 5. 告知の基準

| 告知して進める | 事前にユーザーが決める | 告知しないで進める |
|---|---|---|
| 本線の入れ替え（チャットで出す券の版が変わる）。試験の版の追加・中止（週の振り返りでまとめて） | 新しい取得元、取得量が大きく増えるもの、費用、ユーザーの作業。カード・正式成績・UI に関わる変更 | 分析・集計の追加、取得量を大きく変えない研究用の記録の追加 |

告知はチャットで行い、台帳（§10）と週の振り返りにも残す。

## 6. 今わかっている制約

### 6.1 データの量

- `edge-v0` の券を 2026-10-10〜10-31 の20レースで発走前の最終版から計算すると、的中4回で、投資 10,000円・払戻 14,430円（うち 10/31 東京の 6,900円が大きい）。レースごとの「払戻/投資」の標準偏差はおよそ 3.4。この計算は、ばらつきの目安を出すためのもの。登録（10/21）より前のレースと 10/25 新潟の同着を含むので、`edge-v0` の成績ではない（10/25 までは observe-only の portfolio の反実仮想、10/31 は portfolio-shadow-v1 の記録）。
- この数字で必要なレース数の目安を出すと、次のとおり。どちらも一方向に2標準誤差で見分ける場合で、標準偏差は20レースから見積もった粗い値。
  - 回収率75%と100%を見分けるには、およそ (2 × 3.4 / 0.25)² ≒ **740レース**。
  - 的中の数で、市場どおり（`H/E` = 1）と損益分岐（`H/E` ≒ 1.33）を見分けるには、5点の確率の和を 0.17 として、およそ **180レース**。
- メインレースだけの今の記録は、2026-09-19〜10-31 で33レース（週末に4〜6レース、月に20〜25レース）。このペースだと、180レースに7〜9か月、740レースに2年半〜3年かかる。当日の全レース（1日24〜36、週末に48〜72）に広げれば、180レースは1か月ほど、740レースは3か月ほどで集まる。

### 6.2 オッズの鮮度

- `data/odds_history` の観測75件（2026-09-26〜10-31、28レース）で、取得元が返したオッズの時刻（`source_time`）は、すべて「発走の2〜6分前から1時間刻みでさかのぼった時刻」だった（発走時刻 − `source_time` を60分で割った余りが2〜6分）。観測した時刻と `source_time` の差は、中央値28分・最大61分。取得元のオッズは、およそ1時間おきにしか新しくならない。
- 発走10分前以降の観測は7件。そのうち `source_time` が発走7分前以降（締め切り直前の更新）だったのは5件で、どれも単勝だけの観測か、券種ごとの時刻を残していない古い形式の観測。3連複の締め切り直前の値を取れたと確かめられる観測は無い。
- 例：10/31 東京11R は 15:25:37 に取ったが、4券種とも `source_time` は 14:25:14 だった。3連複 6-9-12 は 12:27 の版で 50.5倍、14:25 の版で 52.9倍、払戻は 6,900円（69.0倍）。
- 意味：研究で使ってきた「発走前のオッズ」は締め切りのおよそ1〜3時間前の値で、最後の1時間の売れ方を含まない。払戻は確定オッズで決まるので、「市場が低く見ている組」を測るには、締め切り直前の更新と確定オッズの記録が要る。
- 更新がおよそ1時間おきになる理由（取得元の仕様か、元の発表の仕方か）は確かめていない。

## 7. 最初の仮説

台帳 [HYPOTHESES.md](reflections/HYPOTHESES.md) に H-025・H-026 を追加し、H-012 を更新した。

1. **H-025 券種どうしのずれ**：同じ時刻の単勝・ワイド（・馬連）から計算した3連複の確率に比べて、3連複のオッズが低く見ている組は、確定オッズの見込みより多く当たるか。単勝の確率から複勝の値打ちを計算した研究（Hausch, Ziemba & Rubinstein, 1981, *Management Science*）と同じ考え方。単勝から2・3着を計算する Harville の式には人気馬を高く見すぎる偏りが知られているので、補正（`harville_trio` の λ）は探す期間だけで決める。
2. **H-026 3連複の人気薄の買われすぎ**：確定オッズの高い組ほど、見込みより当たらず回収率が低いか。人気薄ほど回収率が低い傾向は多くの競馬で報告されている（例：Thaler & Ziemba, 1988, *Journal of Economic Perspectives*）。日本の3連複のどの帯で強いかは確かめていない。これだけで払戻率を越える組が見つかるとは限らないが、他の仮説で選ぶ組から損な部分を外す土台になる。
3. **H-012 締め切り前の売れ方**（既存）：最後の1時間に売れた馬・組が、確定オッズでもまだ低く見られているか。§8.1 の記録ができてから調べる。

既存の market-mix-v1（市場と能力モデルの混合）は、「市場に無い情報」の仮説として前向きに記録中。判定が出たら、混ぜた確率で組む版を試験の版の候補にする。

## 11. 既知の限界

- 前向きの記録だけでは、損益分岐を越える程度の優位を確かめるのに数百レースかかる（§6.1）。データを増やす（§8.2）までは、判断はほとんど「保留」になる見込み。
- 確定オッズの記録ができるまでは `p_pre`（締め切りのおよそ1〜3時間前の市場）で代用する。最後の1時間の動きの分だけ、見込みがずれる。
- 3連複の未収録の組は推定で補っている（portfolio-shadow-v1 §9）。
- 払戻率 0.75 の近似は、組ごとの偏り（人気薄の買われすぎなど）を無視している。H-026 はその偏りそのものを測る。
- 試験の版を3つまでにしても、版を入れ替えながら探す限り、偶然の当たりは完全には除けない。台帳に全部の試行を残し、判断のたびに試した数を書く。
