# 週次の振り返り（反省点・観察仮説・改善候補）

毎開催の結果を見て気づいたことを、**採用・不採用にかかわらず全部ここに溜める**ための置き場所。
溜めた仮説は、データが揃った時点でモデル改善の材料（事前登録する Challenger や v2 ルール）にする。

## ここに書くもの・書かないもの

- 書く：レースごとの事実（着順・人気・印・券の結果）、反省点、観察しておく仮説、改善候補、運用事故とその対処、ChatGPT（チャッピー）など他の分析との比較。
- 書かない：予想ロジック・係数・テンプレート・固定3人・Chappy・オトリゲートの変更そのもの。ここは記録であって、変更の承認ではない。
- このディレクトリの内容は、予想・正式成績・UI・shadow 採点のどれにも読み込まれない（observe-only の文書）。

## 原則

1. **後付けで調整しない。** 結果を見て思いついたことは「仮説」として記録するだけ。採るなら、結果を見る前に事前登録した別の Challenger／v2 ルールで前向きに検証する。
2. **少数レースでは結論を出さない。** 1開催は多くても数レース。各仮説には「何レース分の何を見れば判断できるか」を書いておく。
3. **すぐ取り入れるのは、次の両方を満たすものだけ。**
   - 予想ロジックを変えない（運用・データ収集・検知・表示の修正）、または明らかなバグの修正である。
   - 効果が結果の良し悪しに依存せず説明できる（例：凍結前に最新オッズを取る、評価不能馬を表示する）。
   予想の中身を変えて精度を上げる種類のものは、どれだけ有望に見えても事前登録を経由する。
4. **公開リポジトリなので**、取得元のレスポンス本文・リクエスト固有の値（IP・チャレンジ／Ray ID）・URL のクエリやトークンは書かない。

## ファイル

- [`HYPOTHESES.md`](HYPOTHESES.md)：仮説・改善候補の台帳。ID（H-###）は振り直さない。状態と根拠レースを追記していく。
- `YYYY-MM-DD_開催.md`：開催ごとの振り返り。新しい開催のたびに1ファイル追加する。
  - [`2026-10-10_12.md`](2026-10-10_12.md)：10/10（土）〜10/12（月・祝）の6レース。
  - [`2026-10-17_18.md`](2026-10-17_18.md)：10/17（土）・10/18（日）の6レース。

## 状態の定義（HYPOTHESES.md）

| 状態 | 意味 |
|---|---|
| 観察中 | 既存のデータ（snapshot・race_results・shadow 採点）で、件数が溜まるのを待つ |
| データ収集待ち | 判断に必要なデータがまだ取れていない。先に収集の仕組みが要る |
| 事前登録候補 | 件数・根拠が揃い、Challenger／v2 として事前登録を検討してよい |
| 運用で対処 | 予想ロジックではなく運用・監視で解決するもの |
| 採用 | 事前登録した検証を経て採用された（参照先を書く） |
| 棄却 | 前向きの件数で支持されなかった（理由を書く） |

```markdown
## 3. 観察仮説・改善候補（HYPOTHESES.md の ID を付ける。新規は台帳にも追加）
## 4. 運用・データの事故と対処
## 5. 他の分析との比較（あれば）
## 6. 今週すぐ取り入れたもの／見送ったもの（理由つき）
```
