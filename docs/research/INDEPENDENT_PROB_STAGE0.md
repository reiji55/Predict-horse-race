## 1. 出所の照合

評価の記録（race-performance-v1 の前向きの評価）が見た凍結版を、Stage 0 の側で独立に確かめた。登録済みの評価の記録とコードは変えていない。

- **版の選び方**：main の **first-parent** 履歴で、発走時刻の時点で main に入っていた snapshot の版（発走前にコミットされた最後の版）。ブランチで発走前に作っても、main に入ったのが発走後なら発走前の版にしない（PR #54 と同じ規則）。同じ時刻のコミットは first-parent の順で後のもの。コミット時刻が順に並んでいなければ、順序の照合を unknown にする。
- **照合**（どれも verified・mismatch・unknown の三値。時刻や値が無いことを「合っている」とはしない）：

| 照合 | 中身 |
|---|---|
| `evaluation` | 評価の記録が evaluated |
| `commit_order` | first-parent のコミット時刻が順に並んでいる |
| `snapshot_version` | 選んだ版が `pre_race`、`frozen_at` が発走前 |
| `snapshot_digest` | その版の**生バイトの SHA-256** が評価の記録の SHA-256 と一致（別の版と一致したら `evaluated_other_version`） |
| `race_id`・`frozen_at` | snapshot・評価の記録・評価が残した snapshot の `frozen_at` が一致 |
| `raw` | 同じコミットの raw にそのレースがある |
| `horse_set` | 確率の馬 ＝ snapshot の marks の馬 ⊆ raw の出走馬 |
| `input_raw` | capture の入力 raw の指紋（`input_raw_hash`）が、同じコミットの raw のレースの指紋と一致 |
| `win_odds_timing` | 単勝の source_time ≦ observed_at ≦ コミット時刻、どれも発走前（`market_audit.odds_timing` と同じ判定） |

- 全部 verified のレースだけを「監査済み（audited）」の集計に入れ、記録どおり（as_recorded）の集計と分けて出す。
- **結果：25 レースとも全部 verified**。監査済みの集計は記録どおりの集計と同じ（24 レース・350 頭、平均の単勝 log loss は Champion 2.3364・市場 2.1642）。Issue #57 の初期診断の数字は、この照合のうえで再現した。
- 限界：コミットの時刻（committer date）は操作する人が設定できるので、公開の絶対の証明ではない（順序の確認に使うだけ）。

## 2. 入力の欠け（全頭）

分母を分けた：入力の品質は raw の出走馬の全頭（**368 頭**）、確率の評価は評価の行のある馬（**367 頭**）、市場との比較は市場の確率のある馬（**350 頭**、24 レース）。

- 評価の行が無い馬は 1 頭：10/12 京都 7 番（凍結版の marks に無い。結果の着順にはいる）。全頭の表（`horses.json`）では、p・q・y を null にして理由（`not_in_snapshot_marks`）を付けた。

| 調教師の成績が無い | 118（32%） |

| 過去走が0本 | 0 |

- **騎手の成績の抜けは慢性的**で、ほぼ毎開催日、出走馬の 2〜7 割にある。騎手のリーディング表は上位の騎手しか取れていない（`scraper/common/leading_api.py` のページ送りの注記：jockey は 20 件ずつで 2 ページ目で止まる）。2026-W44 の raw では、成績のある騎手は 27 人で、いちばん少ない勝利数が 23。
- **調教師の成績の抜けは日によって出る**（0 頭の日と、6〜14 頭の日がある）。11/7 の 13:28 の版がいちばん多い（PR #56 で取り直しと補いを入れた）。
- 旗 `leading_stats_partial` は「騎手か調教師の成績の**どちらか**が無い馬の割合が 3 割を超える」（和集合。v1 は二つの大きい方だったので定義を揃えた。旗の数は同じ 21 レース）。旗で除くと 4 レースしか残らず、層別の比較にならない。
- p/q ≥ 2 の区分（77 頭）で騎手の成績の無い馬は 28 頭（36%）で、市場との比較の全体（350 頭中 128 頭、37%）と同程度。**この周辺の集計では、p/q ≥ 2 の「期待 6.34・実勝 1」を欠けだけで説明できる根拠は見当たらない**。ただし、交絡（人気薄ほど成績表に載らない騎手が多いなど）・調教師の欠け・欠けたときの重みの割り直しの効き方は確かめていないので、欠けの影響が無いとは言えない。

## 3. モデルの確率の形

市場との比較の 24 レース・350 頭（記録どおり＝監査済み）。数字は `summary.json` の `strata[0]`（`q_bins`・`p_over_q_bins`・`temperature_sensitivity`・`winner_rank`）。

| 市場の q | 馬 | 市場の期待勝数 Σq | モデルの期待勝数 Σp | 実勝 |
|---|---:|---:|---:|---:|
| < 0.02 | 80 | 0.96 | 2.64 | 1 |
| 0.02〜0.05 | 115 | 3.83 | 5.74 | 0 |
| 0.05〜0.1 | 80 | 5.75 | 5.81 | 11 |
| 0.1〜0.2 | 54 | 7.56 | 6.46 | 7 |
| ≥ 0.2 | 21 | 5.91 | 3.35 | 5 |

- モデルの確率は市場より平らで、人気薄に確率を多く、人気馬に少なく配っていた。p/q ≥ 2 の馬は、ほとんどが人気薄。**今回の標本では、人気薄の勝率の過大推定が観測された**。
- 温度の感度：p を k 乗して正規化し直すと（T ≈ 10/k）、平均 log loss は k = 0.5：2.4238、0.8：2.3543、0.9：2.3426、1（今）：2.3364、1.05：2.3353、1.1：2.3354、1.25：2.3435、1.5：2.3805、2：2.5305。一様は 2.6641。**同じ 24 レースの中の粗い比較で、k = 1 の近くは平らだった**という記述にとどめる（最適な T は、この標本では決められない）。
- 勝ち馬の順位の平均は、モデル 4.38 位・市場 3.44 位（同じ値は平均の順位）。上位3位以内に勝ち馬がいたのは、モデル 12・市場 13（24 レース中）。
- 読み（仮説）：モデルの順位には一様より情報があるが、この標本では市場より弱かった。p > q が人気薄に集まるのは、モデルの情報の不足でも説明できる。ただし、市場が人気薄を見誤っている可能性を、この標本で否定したわけではない。
- 次の評価では、順位の指標・proper score（log loss など）・条件付きの較正（q の区分別・欠けの有無別など）を**並べて**測る。順位が全体で市場並みになることは、エッジの必要条件ではない（全体の順位が弱くても、限られた条件で市場より良い可能性はある）。判断は、事前登録した別の期間で確かめてからにする。

## 4. odds-live の検証（11/7・11/8）

期待の集合は、その日の最後のレース一覧（`check.status` が ok）。レース × 時点（pre・close・post1・post2）× 5券種（単勝・複勝・馬連・ワイド・3連複）で、欠け・状態・時点・post2 の `final_check`（券種ごと）を確かめた。時点が分からない・欠けている・`missed`・`partial`・`failed`・不一致は、どれも成功に数えず `problems` に出す。

| | 11/7（一覧 35 レース） | 11/8（一覧 34 レース） |
|---|---|---|
| pre | ok 28・missed 7 | ok 32・missed 2 |
| close | ok 29・missed 6 | ok 33・missed 1 |
| post1・post2 | ok 35・35 | ok 34・34 |
| ファイルの欠け・一覧に無いファイル | なし | なし |
| 券種の欠け・時点の unknown・発走後の source_time | なし | なし |
| post2 の final_check（5券種ごと） | 全部 verified | 全部 verified |
| 払戻の照合で不明 | なし | 11/8 東京の 3連複・馬連（`combo_not_listed`） |

- `missed` はすべて `started_too_late`（記録を始める前に発走したレース。11/7 は初日の不具合で 10:43 から）。成功には数えていない。
- 一覧のレース数は、場ごとの数（障害戦も数える、計 36）より少ない（11/7 は 1、11/8 は 2）。odds-live は障害戦と発走時刻の無いレースを一覧から外す規則なので、差は問題にせず数だけ残した（外したレースの種別は、この一覧からは確かめられない）。
- `final_check` の `stable_after_close` は「締切後の2回の観測で変わらなかった」ことで、**公式の確定オッズの確認ではない**。
- 払戻との照合は、結果のあるメインの6レースだけ（メイン以外は結果を取っていない）。1行ずつ match・mismatch（ワイドは幅の中・外）・`combo_not_listed`（表に無い組：価格は不明）・`price_unavailable`（その券種の表が取れていない）を付け、まとめは不一致を優先し、次に不明、全部一致のときだけ match とした。
  - 3連複・馬連：5レースで払戻 ＝ オッズ × 100 が一致、11/8 東京は勝った組が表に無い（不明。0 確率でも無限大の倍率でもない、Issue #57）。
  - ワイド：6レースとも払戻が表の幅に入った。
