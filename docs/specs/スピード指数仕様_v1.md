# スピード指数 算出ロジック仕様 v1（Phase 2 タスク3）

入力は共通内部フォーマット（タスク2）の `past_runs`（直近5走）。
出力は馬1頭あたりのスピード指数セット（ベスト値・平均値・信頼度）。
これが4ファクター合成スコア（タスク5）の①の原料になる。

---

## 0. 設計方針：無料データ制約でどこまでやるか

本格派の指数（ベイヤー系・西田式など）は「**同日同場の馬場差**」を使うが、
これはその日の全レース結果が必要で、現在の取得設計（メインレースのみ）では手に入らない。

そこでv1は次の割り切りをする：

- 補正は**3段だけ**：①基準タイム（コース×クラス） ②馬場状態（良/稍重/重/不良のカテゴリ補正） ③斤量
- 各補正の係数は**仮置きの初期値**から始め、成績が貯まったら**後方検証でチューニング**する
  （results.json に配当表を残した設計は、まさにこのためのもの）
- 精密な馬場差推定は将来改良（§6）に回す

「粗くても一貫した物差しで測り、実績データで磨く」がv1の思想。

---

## 1. 1走あたりの指数計算式

past_runs の1件ごとに計算する。

```
scale        = 2000 / dist                    # 距離換算係数
going_sec    = going_adj[surface][going] × (dist / 2000)
impost_sec   = (impost - 55) × k_impost × (dist / 2000)
class_sec    = class_offset[class] × (dist / 2000)

expected_time = base_time[venue][surface][dist] + class_sec
adjusted_time = time_sec - going_sec - impost_sec

指数 = 100 + (expected_time - adjusted_time) × scale × 10
```

- **指数100 = そのコースのOPクラス勝ち馬水準**（基準タイム表の定義。§4）
- 2000mで1秒速い＝+10pt。距離換算により、短距離ほど1秒の価値が大きくなる
  （1200mなら1秒＝約16.7pt）。この換算方式は `scale_mode` で切替可能にしておく（§5）
- 秒ベースの補正はすべて「2000m基準の値 × dist/2000」で距離スケールする

### 1.1 馬場状態補正 going_adj（2000m基準・秒／初期値）

「その馬場でどれだけタイムが**遅くなる**か」。adjusted_time で引き算する。

| 馬場 | 芝 | ダ |
|---|---|---|
| 良 | 0 | 0 |
| 稍重 | +0.5 | **−0.3** |
| 重 | +1.2 | **−0.5** |
| 不良 | +1.8 | −0.2 |

> **ダートは符号が逆**なことに注意。日本のダートは湿ると砂が締まって
> **速くなる**（稍重・重は良より時計が出る）。不良まで行くと逆に脚を取られて戻る。
> 芝は素直に「湿るほど遅い」。この非対称はよく見落とされるので明記しておく。

### 1.2 斤量補正

- 基準斤量 55kg、`k_impost = 0.10`（秒/kg・2000m基準）が初期値
- 57kgで走った馬は「本来もう少し速い」と評価され、軽ハンデ52kgは割り引かれる
- 斤量の実効影響には諸説ある（0.05〜0.2秒/kg）ため、必ず設定値として外出しし、
  後方検証の主要チューニング対象とする

### 1.3 クラス補正 class_offset（2000m基準・秒／初期値）

OPを0とし、下級条件ほど「期待タイムが遅い」方向に加算。

| class | 補正 | | class | 補正 |
|---|---|---|---|---|
| mi（未勝利） | +2.5 | | op | 0 |
| 1win | +1.5 | | g3 | −0.3 |
| 2win | +1.0 | | g2 | −0.6 |
| 3win | +0.5 | | g1 | −1.0 |

### 1.4 検算サンプル

前走：京都 芝1200m 良 OP、走破68.9秒、斤量56kg。京都芝1200の base_time = 67.8 とする。

```
scale      = 2000/1200 = 1.667
going_sec  = 0
impost_sec = (56-55) × 0.10 × 0.6 = +0.06
class_sec  = 0
expected   = 67.8
adjusted   = 68.9 − 0 − 0.06 = 68.84
指数       = 100 + (67.8 − 68.84) × 1.667 × 10 = 100 − 17.3 = 82.7
```

OP勝ち馬水準より約1秒遅い走り ≒ 指数83、という読み方になる。

## 2. 使える過去走の判定（usable run）

以下を**すべて満たす**走のみ指数計算に使う：

1. `time_sec` が null でない（中止・除外・取消は除外）
2. `venue` がJRA中央10場（地方・海外は基準タイム表がないため除外）
3. `surface` が 芝/ダ（障害は除外）
4. `base_time` 表に該当コース（venue×surface×dist）が存在する
5. `class` が正規化表記で判定できる

**芝⇔ダの扱い**：usable には含める（基準タイム表がsurface別なので
「そのsurfaceでの水準」としては正規化されている）。ただし
「ダで指数110＝芝でも110」ではない。この割引は**適性スコア②の仕事**であり、
指数①は surface をまたいだ素の能力測定に徹する（役割分担の明確化）。

## 3. 馬1頭への集約

usable な指数の集合から、以下を出力する：

| 出力 | 定義 |
|---|---|
| `best` | usable指数の最大値（地力の天井） |
| `avg` | **鮮度加重平均**。新しい順に重み `[1.0, 0.9, 0.8, 0.7, 0.6]`（usable分だけ使い正規化） |
| `latest` | 最新のusable走の指数（現在の調子の代理変数） |
| `n_usable` | usable走の本数 |

```json
"speed": {"best": 96.3, "avg": 88.1, "latest": 91.0, "n_usable": 4}
```

- 合成スコア（タスク5）での使い方の目安：`speed_score = 0.6 × best + 0.4 × avg`
  を初期式とし、latest の使い方（調子ボーナス）は合成側で検討
- **n_usable = 0**（新馬・地方転入直後など）：`speed = null`。合成スコアは
  他ファクターのみで計算し、**不確実フラグ**を立てる
- **n_usable ≦ 2**：低信頼。この情報は妙味メーターの
  「レースの予測信頼度」成分（スキーマ仕様v1.1 §3）にそのまま接続する
  （指数の信頼できない馬が多いレース＝予測信頼度が低いレース）

## 4. 基準タイム表（base_time）の作り方

**指数100の定義そのもの**なので、作り方を固定しておく。

- 対象：JRA10場 × 芝/ダ × 施行距離の全コース（約120通り）
- 各コースについて、直近3年の**全クラスの勝ちタイム**を集め、
  クラス補正を引いてOP水準に正規化したうえで**中央値**を取る：

```
base_time = median( win_time − class_offset[class] × dist/2000 )
```

- 中央値を使う理由：日々の馬場差・極端なペースの外れ値に強い
- 全クラスを使う理由：OP以上だけだと年数回しか施行されないコースがあり、
  サンプル不足になるため
- **1回きりの初期構築スクリプト**として実装し（タスク6にサブタスクとして追加）、
  以後は年1回程度の更新で十分。成果物は `config/base_times.json` にコミット
- どのnetkeibaページから勝ちタイム一覧を取るかは実装時（タスク6）に確定。
  一覧系ページを使えばページ数は抑えられる見込み

## 5. 設定ファイル仕様（config/speed_index.json）

チューニング対象をすべてコードから外に出す。重み調整＝このファイル編集＋再計算。

```json
{
  "index_base": 100,
  "point_per_sec_at2000": 10,
  "scale_mode": "distance",
  "impost_ref": 55,
  "k_impost": 0.10,
  "going_adj": {
    "芝": {"良": 0, "稍重": 0.5, "重": 1.2, "不良": 1.8},
    "ダ": {"良": 0, "稍重": -0.3, "重": -0.5, "不良": -0.2}
  },
  "class_offset": {"mi": 2.5, "1win": 1.5, "2win": 1.0, "3win": 0.5,
                   "op": 0, "g3": -0.3, "g2": -0.6, "g1": -1.0},
  "recency_weights": [1.0, 0.9, 0.8, 0.7, 0.6],
  "agg": {"w_best": 0.6, "w_avg": 0.4}
}
```

- `scale_mode`: `"distance"`（距離換算あり・デフォルト）/ `"flat"`（1秒=10pt固定）。
  「短距離の1秒をどれだけ重く見るか」は流派が分かれるため、後方検証で比較できるようにしておく
- `config/base_times.json` は §4 の初期構築スクリプトが生成

## 6. 既知の限界と将来改良（優先順）

1. **馬場差の自前推定**：過去走の「同日同場の他レース結果」を取得すれば、
   その日の馬場の速さを推定でき、精度が一段上がる。取得ページ増と引き換え。
   キャッシュ前提で将来のフェッチャー拡張候補の筆頭
2. **着差ブレンド**：`margin_sec` を使い「勝ちタイム基準の相対指数」と
   素の時計指数をブレンドする案。勝ちタイムに馬場差が織り込まれるため、
   1の簡易代替になりうる
3. **上がり3F の活用**：ペース補正（前傾ラップで飛ばした馬の時計割引）や
   末脚評価。v1では `last3f` を保持するのみで未使用
4. **脚質・通過順位**：共通内部フォーマットの将来拡張とセット
