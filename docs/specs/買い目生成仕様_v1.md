# 買い目生成 ロジック仕様 v1（Phase 2 タスク5）

各馬に **合成スコア（base_score）** を付け、印を打ち、キャラ別のリスク許容度で
買い目（cards[]）を機械生成する。入力はタスク2の共通内部フォーマット（`raw/{week_id}.json`）と
タスク3のスピード指数。出力は predictions.json の `marks[].score` と `cards[]`（スキーマ v1.1 §1）。

本書で確定するもの：
- **合成スコアの中身**（①スピード ②適性 ③人的 の重み付き合成。④は入れない＝下記§0）
- 印の付与ルール
- キャラ別の買い目生成（堅さ↔妙味のブレンド）
- 式別オッズ非取得下での期待値・払戻の近似

スコア→勝率 p への softmax 変換は **妙味メーター仕様 §1 と共有する部品**。本書では再掲のみ。

---

## 0. 設計方針：④オッズ乖離を合成スコアに入れない（最重要）

引き継ぎ書v1§5は「①時計②適性③人的④オッズ乖離の4ファクター合成」と書いていたが、
**④をそのままスコアの材料にすると循環する**。理由：

```
合成スコア → softmax → モデル勝率 p         （§3）
妙味 = p（スコア由来） と 市場q（オッズ由来）の乖離   （妙味メーター仕様）
```

④オッズ乖離をスコアに混ぜると、スコアの中にオッズが入り込み → p がオッズ側に引かれ →
「p と オッズの乖離」で測る妙味が、自分で薄めた乖離を測ることになる（妙味メーターが自分の尻尾を噛む）。

**したがって役割を分離する：**

- **合成スコア（base_score）＝ ①②③のみ**。市場を一切見ない「モデル素の実力評価」。
  これを `marks[].score` に格納し、softmax→p の入力にする。
- **④オッズ乖離は「スコアの材料」ではなく「出力側」に置く**。効かせる場所は2つ：
  (a) 妙味メーター（p vs q、仕様済み） (b) キャラ別の買い目選定（§5）。

この分離は引き継ぎ書の狙いと一致する。「妙味↔的中率の緊張をケイ⇔源さんに担わせる」とは、
**ケイは印（＝①②③の実力）で買い、源さんは妙味（＝④の乖離）で買う**ということ。
④は買い目の層に住むのが正しい居場所であり、スコアの層には降りてこない。

## 1. 合成スコア base_score ＝ ①②③

### 1.1 合成方式：レース内 z 標準化 → 加重和

各ファクターはスケールがバラバラ（①は指数100前後、③は勝率0〜0.25）なので、
**そのレースの出走馬の中で z 値化してから**加重する。

```
z(f)_i = (f_i − mean_race(f)) / sd_race(f)      # ファクター f をレース内標準化
base_score_i = Σ_f w_f × z(f)_i                  # 重み付き和
```

- z 化により「このレースの中で相対的に上か下か」に揃う。頭数やクラスが違っても比較軸が安定
- sd_race(f)=0（全馬同値）のときは z(f)=0 とする（ゼロ除算回避）

### 1.2 欠損の扱い：馬ごとに重みを再正規化

あるファクターが null の馬は、**その馬だけ**残ったファクターで重みを正規化して合成する。

```
使えるファクター集合 F_i について：
base_score_i = Σ_{f∈F_i} (w_f / Σ_{f∈F_i} w_f) × z(f)_i
```

- 例：新馬は①スピードが null（n_usable=0）→ ②③のみで評価し、**不確実フラグ**を立てる
  （不確実フラグは妙味メーター仕様 §2C の信頼度を下げる入力にもなる）
- 全ファクター欠損の馬は base_score=null（印を打たない／買い目にも使わない）

### 1.3 ① 時計（スピード）

スピード指数仕様 §3 の集約値をそのまま使う。

```
speed_raw_i = 0.6 × best_i + 0.4 × avg_i        # スピード指数仕様 §3 の初期式
① = z(speed_raw)
```

- `n_usable ≤ 2` の馬は値は使うが不確実フラグを立てる（低信頼）
- `latest`（調子）の加点は v1 では未使用（将来、合成側の調子ボーナスとして検討）

### 1.4 ② 適性

「今日の条件で実際に走れるか」を過去走の着順から作る。①が「素の時計」なのに対し、
②は「**この条件への当てはまり**」を見る。役割を被らせないのが肝。

**(a) 各過去走を今日の条件との近さで重み付け**

```
prox = w_surface × [芝ダ一致] × ( 1
        + b_dist  × dist_close        # 距離の近さ（|Δdist|/今日dist が小さいほど1に近い）
        + b_venue × [同場]
        + b_going × [同馬場状態] )
```

- **芝ダ一致は最重要（不一致は prox=0 に近い）**。芝の実績はダートの今日にほぼ効かない
- 距離は「近いほど効く」。`dist_close = max(0, 1 − |today_dist − run_dist| / dist_tol)`
- 同場・同馬場はボーナス（係数で調整）

**(b) 着順を頭数正規化してから prox 加重平均**

```
perf = (heads − finish + 0.5) / heads          # 1着に近いほど1、頭数の大小を吸収
② = z( Σ_run prox × perf / Σ_run prox )
```

- 頭数正規化により「16頭立て3着」と「8頭立て3着」の価値差を揃える
- 該当する過去走が0本（同条件を走ったことがない）→ ②は欠損扱い（§1.2 で再正規化）

### 1.5 ③ 人的

騎手・厩舎の着度数（共通内部フォーマット §2.6）から。**分母が小さいと率が暴れる**ので
縮小推定（全体平均へ引き戻す）を必ずかける。

```
rate_shrunk = (hits + α × m) / (starts + m)     # m=引き戻しの強さ, α=全体平均率
```

- 騎手：当該場の複勝率（(wins+seconds+thirds)/starts）を縮小推定
- 厩舎：全体成績で同様
- `③ = z( 0.6 × 騎手rate_shrunk + 0.4 × 厩舎rate_shrunk )`
- `starts` が極端に小さい（例 < m）騎手は自動的に中立（全体平均）へ寄る

### 1.6 初期重み（すべて config・後方検証でチューニング）

```
① 0.45 / ② 0.30 / ③ 0.25
```

> スピード指数仕様と同じ思想：**係数は全部初期値、後方検証でのチューニングが本丸**。
> results.json に `score` と `odds` を残してあるのは、この重みを過去レースで再計算・検証するため。

## 2. 印の付与

base_score の降順に、機械的に付ける。印は**全キャラ共通の「新聞の見立て」**。
キャラ差は印では出さず、買い目（§5）で出す。

| 順位 | 印 | hon |
|---|---|---|
| 1位 | ◎ | true |
| 2位 | ○ | false |
| 3位 | ▲ | false |
| 4〜5位 | △ | false |
| 6位 | ✕ | false |

- 7位以下は無印（marks に載せるが mk 空）。頭数が少ないレースは存在する印だけ付ける
- `marks[].score` には base_score（①②③合成の生値）を入れる。妙味計算・後方検証で使う

---

## 3. スコア → モデル勝率 p（妙味メーター仕様 §1 と共有）

```
p_i = softmax(base_score_i / T)                 # T は妙味メーター仕様 §1 の温度
```

- **同じ base_score・同じ T を妙味と買い目で共有**する（二重定義しない）
- 温度 T の較正は妙味メーター仕様 §7-2 のとおり（最高評価馬の p が過大にならないよう）
- 市場支持率 q（＝1/odds を正規化、控除率割戻し）も妙味メーター仕様 §1.1 と共有

---

## 4. 妙味（p−q）との接続

各馬の **value_i = p_i − q_i**（正＝モデルが市場より高く見ている＝過小評価）を
buy 選定に使う。これが④オッズ乖離の唯一の入口（§0 のとおりスコアには入れない）。

- value のレース内順位を `myomi_rank`（1位＝最も過小評価）とする
- 妙味メーターの値そのもの（0〜100）はレース単位の指標。鳳の降臨判定に使う（§5.4）

## 5. キャラ別 買い目生成

### 5.1 選定スコア：堅さ↔妙味のブレンド

各キャラに **value寄せ係数 λ**（0＝印だけ / 1＝妙味だけ）を持たせ、
base_score 順位と myomi_rank を λ で混ぜて買い目の軸・相手を選ぶ。

```
sel_i = (1 − λ) × base_rank_norm_i + λ × myomi_rank_norm_i
```

- `*_norm` は「1位=1.0 … 最下位=0.0」に線形正規化した順位
- sel の高い順に軸・相手を組む。券種テンプレはキャラごとに固定（下表）

| キャラ | λ | 買い方 | 券種テンプレ（初期） | total |
|---|---|---|---|---|
| 🧑‍🎓 ケイ | 0.15 | 印上位を厚く、堅実 | ワイド軸厚め＋馬連。5点前後 | 500 |
| 👨‍👧 哲さん | 0.40 | 印軸＋少し妙味 | 馬連＋ワイド＋3連複少点数 | 500 |
| 👴 源さん | 0.75 | 妙味馬を軸に散らす | 3連複フォーメーション中心 | 500 |
| 🎩 鳳 | 0.60（広め） | 降臨時のみ・上位互換 | 全券種、点数増 | 1000 |

### 5.2 源さんの線引き（ただのギャンブルにしない）

源さんが軸にするのは「ランダムな大穴」ではなく「**value が大きい＝モデルは高く見るのに人気薄**」の馬。
λが高いので sel 上位に人気薄の過小評価馬が来るが、それでも **base_score が下位すぎる馬（無印相当）は軸に取らない**
（sel 上位でも base_rank が下限を切る馬は除外）。これが「予想アプリ」である証＝妙味に振っても実力の裏づけは残す。

### 5.3 券種確率の近似（式別オッズ非取得のため）

ワイド/馬連/3連複の的中確率は、単勝由来の p から **Harville 式**で近似する。

```
馬連(i,j)  ≈ p_i·p_j/(1−p_i) + p_j·p_i/(1−p_j)
3連複(i,j,k) ≈ 全順列（6通り）の Harville 逐次確率の和
ワイド(i,j) ≈ (i,j が上位3着以内に共存する確率)。3着内の順列から積み上げ
```

- `payout_range` は「近似確率 → フェア配当(1/確率) → 単勝控除率20%で割引」で概算した
  [下限, 上限]。**あくまで概算**（本物の式別オッズが無い）ことを承知で持つ
- 精度が欲しくなったら直前の式別オッズ取得に差し替え。`combo_odds` 予約枠（共通内部フォーマット §2.4）が効く

### 5.4 鳳の降臨と 1000円配分

- 鳳のカードは **`legendary=true`（myomi > myomi_threshold＝80）のレースだけ**生成
  → 通常は3カード（ケイ・哲・源）、降臨レースのみ4カード目に鳳
- 鳳は total=1000。λ=0.60 で軸を取りつつ点数を増やす（全券種ミックス）
- 鳳は「上位互換」＝他3キャラの良いところ取り。ケイの堅い軸＋源さんの妙味相手を厚く買う配分

### 5.5 不変条件（生成時に必ず検証）

1. すべての `amt` は **100円単位**
2. `Σ bets[].amt == total`（ケイ・哲・源=500、鳳=1000）— スキーマ v1.1 の `total` 定義
3. 券種は `ワイド`/`馬連`/`3連複` のみ（単勝・複勝は使わない）
4. `horses` の頭数は券種と一致（ワイド・馬連=2、3連複=3）
5. `horses` の馬番は marks に存在する馬

崩れたら生成エラー（スキーマ v1.1 の生成時検証と同じ思想。ズレを早期検知）。

## 6. 検算サンプル（妙味メーター仕様 §4 と同じ5頭で通す）

妙味メーター仕様 §4 の5頭をそのまま使い、印→キャラ買い目まで通す（クロスチェック）。

| 馬 | base_score | win_odds | p(T=10) | q | value=p−q |
|---|---|---|---|---|---|
| A | 90 | 3.0 | 0.463 | 0.396 | **+0.067** |
| B | 85 | 4.0 | 0.281 | 0.297 | −0.016 |
| C | 80 | 12.0 | 0.170 | 0.099 | **+0.071** |
| D | 70 | 8.0 | 0.063 | 0.149 | −0.086 |
| E | 60 | 20.0 | 0.023 | 0.059 | −0.036 |

```
印（base_score順）:  A=◎ B=○ C=▲ D=△ E=△
base_rank_norm:      A=1.0 B=0.75 C=0.5 D=0.25 E=0.0
myomi_rank（value順）: C>A>B>E>D  → C=1.0 A=0.75 B=0.5 E=0.25 D=0.0
```

**ケイ（λ=0.15）** sel：A=0.96 B=0.71 C=0.58 D=0.21 E=0.04
→ 軸=A、相手=B,C。ワイド A-B / A-C を厚め＋馬連 A-B。**印どおりの堅い買い目。**

**源さん（λ=0.75）** sel：**C=0.875** A=0.81 B=0.56 E=0.19 D=0.06
→ 軸=**C（12倍・▲の過小評価馬）**、相手 A,B,E に散らす。3連複フォーメーション C-A-B / C-A-E。
**同じレース・同じ印でも、源さんの軸には人気薄Cが座る。**

> 読み：C はモデル評価0.170に対し市場0.099（12倍）で最も過小評価。ケイはAで堅く、源さんはCで妙味を取る。
> §0 の「ケイ⇔源さんの緊張」が、追加ルールなしで λ の差だけから自然に出ている。
> C を軸にする源さんの的中率は下がる（人気薄狙い）＝妙味メーター仕様 §3 の緊張とも整合。

## 7. 設定ファイル（config/cards.json）

チューニング対象をすべて外出し。

```json
{
  "score_weights": { "speed": 0.45, "aptitude": 0.30, "human": 0.25 },
  "aptitude": {
    "w_surface": 1.0, "b_dist": 0.6, "b_venue": 0.3, "b_going": 0.2,
    "dist_tol": 400
  },
  "human": {
    "w_jockey": 0.6, "w_trainer": 0.4,
    "shrink_m": 10
  },
  "marks": { "hon_rank": 1, "maru": 2, "sankaku": 3, "delta": [4, 5], "batsu": 6 },
  "characters": {
    "kei":   { "lambda": 0.15, "total": 500, "max_points": 6 },
    "tetsu": { "lambda": 0.40, "total": 500, "max_points": 6 },
    "gen":   { "lambda": 0.75, "total": 500, "max_points": 8, "axis_base_rank_floor": 6 },
    "otori": { "lambda": 0.60, "total": 1000, "max_points": 12 }

```

- `axis_base_rank_floor`：源さんが軸に取れる base_score 順位の下限（§5.2）
- softmax の温度 T・myomi_threshold は妙味メーター仕様側（config/myomi.json）と共有し、二重定義しない
