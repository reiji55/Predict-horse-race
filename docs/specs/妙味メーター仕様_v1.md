# 妙味メーター 計算式仕様 v1（Phase 2 タスク4）

妙味メーター（myomi・0〜100）を確定させる。定義は「オッズと当モデル評価の乖離＝期待値の旨み」。
閾値超（サンプル80）で `legendary=true`＝鳳降臨。

入力は 合成スコア（タスク5）由来の**モデル勝率 p** と、フェッチャー由来の **単勝オッズ**。
出力は各レースの `myomi`（0〜100）と、将来の2軸分割に備えた内訳（旨み度・堅さ）。

---

## 0. 設計方針と、旧構想からの1つの変更

引き継ぎ書§4の妙味の材料は3つだった：
①モデル勝率とオッズ支持率の最大乖離 ②**期待値プラスの買い目の本数** ③予測信頼度。

このうち②「買い目の本数」は、ワイド・馬連・3連複の**式別オッズ**が必要になる。
だがタスク2で式別オッズはMVP非取得（単勝から近似）と決めた。組み合わせ本数を
approximateなオッズで数えると妙味が近似の上に近似を重ねることになる。

そこでv1は②を **「勝率空間での過小評価の広がり」** に置き換える。
単勝オッズと p だけで計算でき、combo_odds に依存しない。意味は同じ
（＝旨みのある馬がどれだけ広くいるか）で、材料が軽く堅牢になる。
**これは旧構想からの意図的な変更点なので明記しておく。**

結果、v1の妙味は3成分：
- **A. 旨みの深さ**（最大EVエッジ）… ①に相当
- **B. 旨みの広がり**（過小評価の総量）… ②の代替
- **C. 予測信頼度**（データの揃い具合）… ③に相当

A・Bが「旨み度」、Cが「堅さ」。**この2つは将来2軸に割る時そのまま使える**（§5）。

## 1. 前段：スコア → モデル勝率 p への変換

妙味も買い目（タスク5）も、合成スコアを**勝率の分布**に直す共通処理を必要とする。
ここで定義し、タスク5と共有する（合成スコアの中身＝4ファクター合成はタスク5の担当）。

```
p_i = softmax(score_i / T) = exp(score_i / T) / Σ_j exp(score_j / T)
```

- `T`（温度）：分布の尖り具合。低T＝1強に集中、高T＝横並び。
  **Tはモデルが市場とどれだけ「意見が違う」かを直接左右する** → 妙味水準と鳳頻度の主要ツマミ
- **注意**：合成スコアのスケール（タスク5）が決まるまで T は仮値。
  スコア定義後に「最高評価馬の p が過大にならない」よう較正する（本丸のチューニング対象）
- 合成スコアが null の馬（新馬等）は softmax から除外し、Cの信頼度を下げる

## 1.1 市場支持率 q（オッズ側の確率）

単勝オッズから市場が見込む勝率を復元する。

```
r_i = 1 / win_odds_i          # 生の暗黙確率（控除率を含む）
q_i = r_i / Σ_j r_j           # 正規化した市場支持率（Σq = 1）
```

- 生の Σr_i は約 **1.25**（＝1/(1−控除率)。単勝控除率20%）。この上振れ＝オッズに
  埋め込まれたハウスエッジ。正規化 q はこれを割り戻した「純粋な人気分布」
- **正直さの核心**：ある馬が支持率より過小評価でも、控除率ぶん（約25%）以上
  過小評価されていないと期待値はプラスにならない。「妙味あり」の敷居は
  ハウスエッジのぶん高い。この事実を煽らず数式に織り込む
- `win_odds` が null の馬は Σ から除外し、欠損が多いレースはCを下げる

## 2. 3成分の計算

### A. 旨みの深さ（最大EVエッジ）

各馬の単勝期待値 `EV_i = p_i × win_odds_i`（1円あたり期待払戻）。1.0超で期待値プラス。

```
A_raw  = max_i(EV_i) − 1          （0未満は0にクランプ）
A_norm = min(A_raw / edge_cap, 1)  （edge_cap=0.5：+50%エッジで飽和）
```

- 最も過小評価された1頭の旨みの深さ。大穴・一撃（源さん）と親和

### B. 旨みの広がり（過小評価の総量）

```
B_raw  = Σ_i max(p_i − q_i, 0)      （正の乖離だけ合計。0〜約1）
B_norm = min(B_raw / breadth_cap, 1) （breadth_cap=0.4）
```

- Σp=Σq=1なので、正の乖離合計＝負の乖離合計。市場との「意見の食い違い」の総量
- 広く食い違う＝3連複で散らす旨みがある。哲さん・源さんの多点買いと親和

### C. 予測信頼度

```
data_cov = （n_usable ≥ usable_run_min を満たす馬の数）/ heads
conf     = conf_floor + (1 − conf_floor) × data_cov
```

- `usable_run_min=3`, `conf_floor=0.5`。時計データの揃った馬の割合が主ドライバ
- データが薄いレースは旨みを信用しきれない → エッジを割り引く（＝安易に鳳を出さない）

### 合成

```
旨み度(raw)  = w_edge × A_norm + w_breadth × B_norm      # w_edge=0.6, w_breadth=0.4
myomi = clamp( 100 × 旨み度(raw) × conf , 0, 100 )
legendary = myomi > myomi_threshold（=80）
```

## 3. 「妙味が高い＝当たりやすい」ではない、が式に内在すること

この緊張（引き継ぎ書が強調）は、**追加のペナルティを入れなくても式に組み込まれている**：

- A・Bが大きい＝モデルが市場と食い違う＝**人気薄を評価している**
- 人気薄を狙う買い目は的中率が下がる
- ゆえに myomi が高いレースほど、構造的に的中率は下がりやすい

妙味は「期待値の旨み」を測り、的中率は測らない。両者が引っ張り合う関係は
ケイ（堅く当てる）⇔源さん（旨みを取る）のキャラ対立がそのまま担う。**式は旨み一本に徹する。**

confは「当たりやすさ」ではなく「モデルを信じてよいか」。的中率とは別軸。

## 4. 検算サンプル（簡略化のため5頭で図示）

| 馬 | score | win_odds | p (T=10) | r=1/odds | q |
|---|---|---|---|---|---|
| A | 90 | 3.0 | 0.463 | 0.333 | 0.396 |
| B | 85 | 4.0 | 0.281 | 0.250 | 0.297 |
| C | 80 | 12.0 | 0.170 | 0.083 | 0.099 |
| D | 70 | 8.0 | 0.063 | 0.125 | 0.149 |
| E | 60 | 20.0 | 0.023 | 0.050 | 0.059 |

```
EV: A=1.39 B=1.12 C=2.04 D=0.50 E=0.46   → max=C(2.04), A_raw=1.04 → A_norm=1.0
p−q(正): A=+0.067, C=+0.071             → B_raw=0.138 → B_norm=0.345
data_cov=1.0, conf=0.5+0.5×1.0=1.0
旨み度 = 0.6×1.0 + 0.4×0.345 = 0.738
myomi  = 100 × 0.738 × 1.0 = 73.8  → 80未満、鳳は降臨せず
```

読み：C（モデル0.170 vs 市場0.099、12倍）が過小評価の主役。妙味74＝高いが確変ではない。
狙う軸はCという人気薄なので的中率は下がる ＝ §3の緊張がそのまま出ている。

> 実際の18頭立てでは Σr≈1.25 になる（この5頭例は overround<1 の簡略値）。
> 正規化 q が overround を吸収するので、頭数が変わっても式は同じ。

## 5. 将来の2軸分割（設計済みの逃げ道）

引き継ぎ書の「1本を旨み度＋堅さの2軸に割る案」は、v1で内訳を残せば無改修で実現できる：

```json
"myomi": 74,
"myomi_parts": { "umami": 0.738, "conf": 1.0 }   // umami=旨み度, conf=堅さ
```

- UIを2メーター表示に変えたくなったら、この2値をそのまま出す
- predictions.json に `myomi_parts` を持たせるか（UI将来対応）／持たせないかは要確認（§7）

## 6. 後方検証との接続（運用者の仮説の検証）

marks に `odds` と `score` を残した目的（スキーマ§3）は、まさにこれ：

- results.json が貯まったら「**myomi 80超のレースは実際に回収率◯%だったか**」を後方検証
- 検証で「妙味が高いほど回収率が高い」傾向が出れば、運用者の原点仮説
  （参加者の少ないレースはオッズが歪む→期待値が出る）そのものが裏づく
- 傾向が出なければ edge_cap / T / 各weight を調整。**この較正ループが精度の本丸**

## 8. 設定ファイル（config/myomi.json）

```json
{
  "prob_model": { "method": "softmax", "temperature": 10.0 },
  "components": {
    "w_edge": 0.6, "w_breadth": 0.4,
    "edge_cap": 0.5, "breadth_cap": 0.4
  },
  "confidence": { "conf_floor": 0.5, "usable_run_min": 3 },
  "myomi_threshold": 80
}
```

※ `myomi_threshold` は predictions.json トップレベルの値と一致させる（スキーマ§1）。
