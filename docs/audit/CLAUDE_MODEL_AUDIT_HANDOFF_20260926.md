## 1. 最終目的

単純な「勝ち馬当て」ではなく、パリミュチュエル市場で **モデル評価と市場評価のズレ（歪み）を拾い、最終的な馬券ROIを高める**ことが目的です。

したがって、評価すべき対象は少なくとも次の3層に分かれます。

1. 馬の能力・好走可能性をどれだけ正しく推定できるか
2. 市場オッズとのズレをどれだけ有効に抽出できるか
3. 良い予測シグナルを、買い目生成が壊さず馬券へ変換できているか

特に3番目が現在の主要論点です。

## 4. Win Score と Top3 Score を分けた理由

現行設計では、
- `base_score`: 勝ち切る力の順位
- `top3_score`: ワイド / 3連複の相手候補用

として分離しています。

背景:
「勝てる馬」と「3着内に来やすい馬」は同じとは限らず、Win側の順位だけでワイドや3連複の相手を作ると、相手選定の情報が弱いという問題意識がありました。

そのため `top3-partner-v1` をChallengerとして並走させています。

ただし現時点で、
- Win確率 p は未校正
- Top3 Score も未校正
- どちらも「真の確率」とは扱っていない

という制約があります。

## 7. Context Layers

現在、以下の当日情報を「observe_only」で収集しています。

- 馬場指標
- オッズ推移

4. Challengerで検証
5. Champion昇格は共通レースの前向き成績で判断

という順序を守るためです。

「情報が取れるから即重みに入れる」という方針ではありません。

## 8. 自動Chappy (`chappy-signal-v1`)

現在の自動Chappyは、固定3人とは別の1000円統合判断レイヤーです。

入力シグナル:
- win
- top3
- condition
- recent
- market
- value

base_weights:
- win 0.30
- top3 0.25
- condition 0.20
- recent 0.15
- market 0.10

その後、役割ごとにさらに別重みを適用し、

- win_anchor
- support
- top3_edge
- long_edge

を **重複なしで4頭** 選びます。

さらに固定の9点ポートフォリオへ流します。

典型:
- ワイド core
- ワイド insurance
- ワイド edge
- 馬連
- 3連複 複数

### 現在疑っている構造問題
この仕組みは「情報を広げる」のではなく、実際には

複数シグナル  
→ 正規化  
→ 重み付け  
→ 役割別重み付け  
→ 4頭へ圧縮  
→ その4頭で買い目展開

となっています。

つまり **点数は多いが、仮説の幅が狭い**可能性があります。

## 12. 特に重要な仮説: 「モデル高評価 × 市場低評価」

チャット上で現在最重要視している論点です。

> モデル側には複数の根拠があるのに、市場では人気がない馬

これは市場の歪みそのものかもしれません。

もちろん、
- 人気薄だから買う
- モデル順位が高いだけで買う

では不十分です。

候補としては、
- base_score 上位
- Top3も上位
- 適性/近況にも裏づけ
- データ品質が低くない
- なのに市場人気だけ低い

という馬を、**市場人気の弱さだけで格下げせず、独立したedgeとして保護する**必要があるかもしれません。

現在の懸念:
Chappyのmarket/value処理や、最終的な手動判断で
「人気がない = 怪しい」
として、狙うべき歪みを潰している可能性。

Claudeにはここを特に監査してほしいです。

## 13. 市場情報の役割に関する未解決点

市場には2つの役割があります。

1. 集団知として予測に使う
2. モデルとの差を価格歪みとして使う

この2つを同じ方向に混ぜると、

「市場が低評価なのでモデル側も下げる」
→ 「市場とのズレが消える」

という自己矛盾が起きます。

レビューしてほしいこと:
- market signal を能力評価に入れるべきか
- value / q をどの段階で使うべきか
- 市場は veto なのか、price-only signal なのか
- `model support × market disagreement` を独立特徴として持つべきか

## 14. 正規化による情報破壊の可能性

Chappyでは `_norm()` でレース内 min-max 正規化しています。

懸念:
- 実値差が非常に小さくても0〜1に拡大される
- 欠損や外れ値で順位差が過大化する
- valueが微小/負でも相対順位だけで大きく見える可能性
- signal間で「本来の信頼度」が失われる

固定3人の `sel` 側にもrank normalizationがあります。

Claudeには、
- rank/min-max normalizationが「買い目用ランキング」には妥当か
- 実値差を捨ててよい箇所 / 捨てるべきでない箇所
- 小さなedgeの誇張
を監査してほしいです。
