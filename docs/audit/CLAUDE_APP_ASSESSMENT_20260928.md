## 1. なぜ 9/22・9/26 の当たりが続かなかったか（Claude の見立て）

1. **当てたのは別々の仕組み。** 9/22 は手動チャッピー、9/26 は固定3人。「同じものが急に弱くなった」のではなく、「別々のものが、たまたま別の日に当たった」。
2. **予想ロジックは 9/26 と 9/27 でほぼ同じ。** チューニングで悪くなったのではなく、同じモデルが9/26は当たり、9/27は外れた。
3. **穴狙いは連敗するのが普通。** Gen 型の的中率は1レースあたり数%〜10%程度の想定。的中率10%なら5連敗の確率は約59%、10連敗でも約35%。
4. **数レースでは何も判定できない。** 的中率10%・当たれば平均12倍（回収率120%）の戦略と仮定した場合の、回収率の誤差の目安（±2σ）:

| 検証したレース数 | 回収率の誤差の目安 |
|---|---|
| 100レース | ±約72% |
| 1000レース | ±約23% |

→ 100レースでも、回収率120%の戦略と80%の戦略を見分けられない。1日の結果でチューニングすると、ほぼ確実にノイズに合わせてしまう。
→ 「9/26の動き」は、狙って再現できる動作ではなく結果。再現を目指すなら「期待値がプラスの買い方」を作るしかなく、それは過去データでしか検証できない。

## 2. 良いところ

- 発走前データの凍結、発走後の書き換え防止、後出しを防ぐ検証（snapshot SHA・git 時刻）、本番と実験の分離、監査の記録。
- 個人の競馬プロジェクトとしては珍しく「後から都合よく解釈できない仕組み」ができている。強みが見つかったとき、それが本物か確かめる土台はすでにある。

## 3. 弱いところ（核心）

1. **予想の材料が、オッズにすでに入っている公開情報の一部しかない。**
   - 使っているのは適性・騎手・調教師くらい。
   - スピード指数は芝でほぼ止まっている（`base_times` は芝が中山の1200/1600/1800/2000のみ）。
   - 直近の調子の重み付け、クラス、展開・脚質のデータが無い。
   - オッズは何万人分の情報が集まった強い予測。材料が少ないモデルが市場と意見が分かれたとき、間違っているのはたいていモデルの側。
2. **「割安な馬を探す」仕組みが逆に働いている可能性が高い。**
   - 今は「モデル確率 p − オッズの確率 q」が大きい馬を狙っている（Kei/Tetsu は p−q、Gen は EV）。
   - p が過去データで調整されていない（`softmax(score/T)`、T=10 は手で決めた値）。
   - そのため差が大きい馬は「本当に割安な馬」より「モデルが読み違えている馬」になりやすく、弱い馬に系統的に賭ける構造になっている。9/27 の「3人とも同じ軸」もこの延長。
3. **仕組みの複雑さに対して、データが足りない。** 本命・挑戦者・レース判定・チャッピー・大鳥ゲート・コンテキスト層・shadow 実験と層は多いが、検証できたレースは十数件。どの層が効いているか原理的に判別できない。
4. **重みや温度がすべて手で決めた値。** 過去データに当てはめて決めた値が1つも無い。
5. **締切直前のオッズで買えていない。** GitHub Actions は4〜5時間遅れて動くことがあり、買うときのオッズと計算に使ったオッズがずれる。
6. **ChatGPT の手動判断に、検証できる強みがない。** 9/22 は見事だったが、1回では判定できない（decision log による前向き記録は PR #14 で整備済み）。

## 4. 改善案7つ（Claude の優先順）

| # | 案 | 中身 |
|---|---|---|
| ① | 過去データの土台を作る | 数年分のJRA全レースの結果・確定オッズ・払戻・馬ごとの過去走。現実的な入手手段は JRA-VAN（公式の有料データ、月額数千円程度） |
| ② | 「オッズ＋自分のモデル」を合わせる形に作り直す | 過去走から作る指数（芝・ダート全コース、馬場差補正）、直近成績、クラス、距離・コース適性、枠、斤量、間隔、騎手で勝つ確率のモデルを過去データで学習。そのうえで「オッズの確率とモデルの確率をどれだけ混ぜると一番当たるか」を過去データで決める（Benter方式の2段階: `log p_final = α·log p_model + β·log q_market`） |
| ③ | 賭ける前に「続けるかどうか」を判定する | 学習に使っていない期間で、「オッズ＋モデル」が「オッズだけ」より良い（log loss が小さい）か確かめる。良くならなければ強みは無いので、賭けない、または最小額 |
| ④ | 買い目は期待値で決める | 「当たる確率 × 締切直前のオッズ」が1を十分に上回る組だけを買う。固定テンプレはやめる。見送るレースが多くて普通。賭け金は固定の少額か Kelly 基準の1/4程度 |
| ⑤ | 締切直前に確実に動く実行環境 | 遅れない cron（安いVPS等）に移すか、締切10〜15分前に手動実行 |
| ⑥ | 評価は数百レース単位 | メインレース以外にも対象を広げる。1日の結果で設定をいじらないルールにする |
| ⑦ | それまでは層を増やさない | 今の本命モデルは凍結。新しい層は①〜③ができてから |

**期待値についての正直な見通し:** 控除率を上回り続けるのは個人ではかなり難しい。現実的な目標は「まず回収率を80%台から95〜100%に近づけ、そのうえで強みのある狭い条件を探す」。穴狙いを続けるなら、大当たりと長い連敗はセットなので、賭け金を小さく固定して100レース単位で判断する。
