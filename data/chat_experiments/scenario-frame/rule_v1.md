# scenario-frame / v1 — 発走前事前登録ルール

- Status: 登録版。このファイルが main に最初にコミットされた時刻を v1 の登録時刻とする。以後このファイルは書き換えない（変えるなら rule_v2.md を別に登録する）
- Experiment ID: scenario-frame
- Version: v1
- Author: ChatGPT（仕様提案）。main への登録コミットは Claude が GitHub API 経由で行う
- Comparison: 現行 Champion の gen（源さん）、予算各500円／レース
- Derived-from / development set: 2026-10-10 京都11R・東京11Rの結果後監査。この2レースはv1の前向き評価に含めない。
- Reference implementation: data/chat_experiments/scenario-frame/reference_v1.py（このファイルと同じコミットで登録する）。記録はこの script の出力をそのまま使う。本文と script の食い違いが後で見つかっても、v1 の記録は書き換えず、その事実を残して v2 で直す。

## 1. 仮説と対象

従来の源さんは共通の能力順位／キャラ固有のEV順位から軸を固定して3連複を組むため、総合順位の低い馬が「別の好走根拠」を持っていても候補から落ちやすい。能力上位（A）、条件・格の実績（B）、合理的な巻き返し材料（C）を独立に拾い、単一軸に依存しない買い目へ変換すれば、この候補落ち／券への変換落ちを減らせるかもしれない。

- 対象: このファイルのコミット以降に発走する、プロジェクトの週末3CARDSパイプラインが対象とするJRA 11Rの芝・ダート平地競走。初回対象は2026-10-11東京11R・京都11R。未勝利・障害・地方競馬・浦和Chappyは対象外。
- フィールドが3頭未満、または snapshot／raw の整合性を確認できない場合は、買い目を生成しない。後者のデータ取得事故は「実験の見送り成績」ではなく、記録の欠落として明示する。
- v1は予想モデルの精度向上が証明されたものではない。既存の Champion / RPS Challenger / speed-v2 Challenger のいずれとも別の、ChatGPTチャットでの前向き実験。

## 2. 入力、出走馬の同定、時刻の固定

1. GitHub main のraw/{week_id}.json中の races[].id = race_id と、data/snapshots/{race_id}.json のChampion発走前凍結記録を使用する。week_id は対象日のISO週（例: 2026-10-11 = 2026-W41、2026-10-12 = 2026-W42）。snapshot_ref.frozen_at はファイルの値を1文字も変更せず転記。raw は、使う snapshot の版をコミットしたのと同じコミットの版を使う（パイプラインは raw と snapshot を同じコミットに入れる）。reference script は、main 上でその snapshot を最後に更新したコミットから raw と snapshot の両方を git で読み、そのコミットの SHA を summary に記す。
2. Champion snapshot の pre_race が true、frozen_at <= created_at < race日付+post_time(JST) であることを要する。未来時刻・発走後・読込失敗は予想を出力しない。created_at は出力生成の実測JST、偽の固定時刻を入れない。
3. 同一実行中のrawとsnapshotを取り違えないよう、利用した raw のGitコミットSHAをsummaryに短く記す。rawの過去走は対象レースの発走前に存在したもののみを使う。結果、払戻、着順確定、発走後に追加された情報を絶対に使用しない。
4. 全頭を記録：snapshot.marks の全馬を num 昇順で candidates に載せる（記録の検証は snapshot の出走馬と照合する）。raw.entries と snapshot.marks の番号集合が違う場合は、取消・除外の公式発走前情報と照合して解決するまで生成停止。raw にだけいる取消・除外馬は candidates に載せず、summary に馬番を記す。snapshot にいる取消・除外馬は候補に残すが、frames: []、evidence: "発走前取消／除外" とし、券には使わない。
5. 現行 raw には取消判定の一貫した専用フィールドが存在しない。利用可能なら当日のJRA公式の取消・除外発表を別途検証する。公式確認不能で出走状態に疑義がある場合は生成停止。未確認を「出走確定」と断言しない。確認した取消・除外の馬番は reference script に --scratched で渡す（無ければ渡さない）。取消／除外でない全馬を一律に同じルールで評価する。
6. snapshot.marksの順番を共通能力順位（base_rank: 1始まり）とし、marks[].top3_rank をTop3順位とする。欠損は無限大（∞）扱い。市場オッズ、人気、race結果はA/B/Cの入枠判断・同順位裁定に使わない。
7. 比較用の源さんカード（snapshot.cardsの char="gen"）は後で表示してよいが、scenario-frameの枠・券はその買い目に合わせて変更しない。
8. 記録は1レース1件で、一度作成したら上書き禁止。初回作成タイミングは原則当日12:30 JST。12:30に必要データが揃わず作成できない場合だけ、当日15:00 JSTに初回作成を再試行する（発走前限定）。12:30に出力したJSONがあれば15:00に再計算・再提出して置き換えず、同一のJSONをそのままコミットする。15:00の最新オッズや別案は実験外の参考コメントとし、v1の candidates・betsを差し替えない。発走前の原本が作れなければ、そのレースは記録欠落。

## 3. 過去走の共通フィルター

- 入力は raw.entries[].past_runs の先頭5走のみ。run.date < race.date、日付ISO形式、同じ surface（芝／ダート）、abs(run.dist-race.course.dist) <= 400m、クラス・着順・着差が正常値の走だけB/C判定の材料に使う。
- finish は正の整数、heads が存在する場合 finish <= heads。margin_sec は有限数かつ >= 0。impost は有限数のみ有効。無効・欠損の走を補完・推定しない。
- クラスの強弱を次の順序で扱う：mi(0) < 1win(1) < 2win(2) < 3win(3) < op(4) < g3(5) < g2(6) < g1(7)。知らないクラスはB/Cに使わない。対象の race.grade がこの表にない場合はCの「クラス制限」を判定できないのでそのレースをpassとする。
- 「2歳戦」は、取消馬を除くraw.entries[].ageが全て整数2であるレースだけ。年齢欠損や混在時は2歳特例を適用しない。
- 「ハンデ戦」はrace.course.noteにハンデという文字列が含まれる場合だけ。

## 4. 3つのシナリオ枠（同時所属可）

全出走馬をまず各枠の資格判定にかけ、その後各枠の上位だけを採用する。framesは人数上限を適用した後の所属を記録する。資格を満たしても上限外の馬は、その枠の frames に載せない。

### A: 安定・実力型（最大3頭）

- 資格: Champion共通能力順位 base_rank <= 4 または top3_rank <= 3。
- 採用の順序: (min(base_rank,top3_rank), base_rank+top3_rank, base_rank, 馬番) の辞書式昇順。欠損順位は ∞（∞+値=∞）。上位3頭をAに採用。
- 根拠テキスト: A 共通順位X位・Top3順位Y位（欠損は欠損）。

### B: 条件・実績型（最大2頭）

- 共通フィルターを満たす過去走のうち、いずれか1走が次の条件を満たせば資格あり。
  - B1：上級クラス class >= opかつfinish <= 3。
  - B2：同開催場・近距離の同格以上 run.venue == race.venueかつabs(dist差) <= 200mかつclass_rank(run.class) >= class_rank(race.grade)かつfinish <= 3。
- B1/B2のいずれも一律に判定（2歳戦でも他条件でも同じ式）。2歳OP実績はB1で拾う。
- 複数資格走からベスト1走を選ぶ順序は (-過去クラスrank, -同場フラグ, 距離差m, 着順, 着差秒, -過去走日付, 過去走の入力位置) の辞書式昇順。
- B枠内では各馬のベスト1走を同順序で並べ、最後に馬番昇順で同点裁定。上位2頭を採用。
- 根拠: どの B1/B2、何年何月何日・場・芝ダ・距離・クラス・何着・着差秒を残す。

### C: 巻き返し・上昇型（最大2頭）

- 共通フィルターを満たす走のうち、class_rank(run.class) >= max(0, class_rank(race.grade)-1)を満たし、いずれかが真なら資格あり：
  - C1：小着差の敗走：4 <= finish <= 8 かつ margin_sec <= 0.7。
  - C2：斤量減で巻き返す可能性：今日がハンデ戦、2 <= finish <= 8、margin_sec <= 1.2、run.impost - today.impost >= 2.0kg。
  - C3：距離変更で再評価：2 <= finish <= 8、margin_sec <= 0.5、200 <= abs(dist差) <= 400m。
- 1走が複数を満たす場合は C1 > C2 > C3 をその走のラベルとする。過去走のベスト1走は (C番号1/2/3, 着差秒, -過去クラスrank, 距離差m, -過去走日付, 過去走の入力位置) で選ぶ。
- C枠内では同じ順序、最後に馬番昇順。上位2頭を採用。
- 根拠: C1/C2/C3と日付・クラス・着順・着差・距離差、C2なら過去と今回の斤量を記す。

複数所属：A/B/Cに同時に選ばれてよい。framesは常に A,B,C の順で重複なし。どの枠も0頭の場合はその枠を無理に補充しない。A/B/C以外の「例外枠」は設けない。

## 5. 買い目の機械的生成（予算500円、100円単位）

1. 取消・除外でなく、少なくとも1つの枠に採用されたユニーク馬の集合をPとする。|P| < 3または Aが0頭または BとCが合計0頭の場合はpass。
2. Pの全3頭組合せを作る。各券に対し、A/B/Cの枠と各馬の間の重複なし対応付けの最大数diversity（1〜3）を求める。diversity >= 2 の3連複だけが候補（3頭は馬番昇順）。
3. A/B/Cの各枠内順位を1,2,3...とし、各馬の最小順位をbest_rankとする。候補3連複の固定順位の決め方は以下の貪欲法。選ぶときには、それまでの券での各馬の採用回数exposureを使い、次のタプルの辞書式昇順の券を選ぶ：( -diversity, 選択後の3頭のexposureの最大値, 選択後の3頭のexposure合計, -今回初めて出る馬ペアの数, 3頭のbest_rank合計, 3頭の馬番の昇順タプル )。採用後、対応するexposureと登場馬ペアの集合を更新する。最大5券まで3連複100円で採用。
4. 3連複が0件ならpass。5件あれば3連複5点×100円＝500円で終了。4件以下なら、Pの全2頭ペアからdiversity >= 2のワイドを追加する。各ペアは1枚ずつ100円、タプル ( -diversity, 選択後の2頭のexposure最大, 同合計, -未登場ペアフラグ, best_rank合計, 馬番昇順タプル ) の辞書式昇順で選ぶ。ワイド候補が無くなるまで追加し、500円に達するまで繰り返す。
5. ユニークなワイドペアを一巡しても予算が残る場合は、最初に選んだワイド1点に100円ずつ増額する（ワイドも無い場合は3連複の先頭1点に100円ずつ増額）。券種と馬番が同じ券は配列に二重行として置かず、金額を合算。合計は必ず500円。馬連はv1では使わない（許可券種だが定型生成対象外）。
6. frame_tag はその券の馬に異なる枠を1つずつ割り当てて得られる最大対応の枠ラベル集合（例：A+B+C、A+C）。最大対応が複数あれば、まず割り当て枠の順位合計が最小、次に 馬番昇順に並べた馬へのラベル割当文字列 が辞書式最小のものを使う。ラベルは+で連結してA/B/C順。どの券も frame_tag を持つ。
7. 同点時は必ず馬番昇順。同一の入力で同一のカードを出力し、事後の裁量による券の差し替えを認めない。価格による選別もv1には入れない。
8. 買い目はtype=3連複またはワイド、horsesは昇順の馬番配列、amtは100円の整数倍。配列の順番は採用順（3連複→ワイド）。

## 6. 見送り・入力不備

- 実験上のpass：対象レースだが、正常に必要データを読み込めたうえで、|P|<3、A=0、B+C=0、diversity>=2の3連複候補が0、またはrace.grade不明。action="pass"・bets=[]・pass_reasonはこの具体的な理由、candidatesは読み込めた全出走馬について必ず記録する。budget=500は比較用の上限であり、見送り時の実投資は0円。
- 欠測・不整合でレースそのものの判定が再現できない場合（raw/snapshot読込不可、両者の出走番号が説明なく不一致、取消状況不明、created_atが発走後など）は、推測した偽のJSONを作らない。未生成の理由を人間へ報告し、データが取得できれば発走前に再試行する。欠損を勝手にpassとして30レースの分母に含めない。

## 7. 発走前JSONの契約

1レースにつき1ファイル。保存先は data/chat_experiments/scenario-frame/races/{race_id}/{YYYYmmddTHHMMSS}.json（ファイル名は created_at の JST）。この置き場所以外の記録は検証・採点の対象にならない。reference script（--write）はこの置き場所にだけ書き、同じレースの記録が作業ツリーか main の履歴に既にあれば書かない。rule_ref.pathはこのMDのGitHubパスをそのまま使用する。

```json
{
  "schema_version": "chat-experiment-record-v1",
  "experiment_id": "scenario-frame",
  "rule_ref": { "path": "data/chat_experiments/scenario-frame/rule_v1.md", "version": "v1" },
  "race_id": "YYYYMMDD-venue-11",
  "created_at": "発走前の実測JST ISO8601+09:00",
  "author": "記録を生成した者（ChatGPT または Claude）",
  "snapshot_ref": { "path": "data/snapshots/{race_id}.json", "frozen_at": "実際のsnapshotの値" },
  "baseline_char": "gen",
  "budget": 500,
  "action": "bet または pass",
  "pass_reason": null,
  "candidates": [ { "num": 1, "frames": ["A"], "evidence": "A 共通順位…" }, { "num": 2, "frames": [] } ],
  "bets": [ { "type": "3連複", "horses": [1, 2, 3], "amt": 100, "frame_tag": "A+B+C" } ],
  "summary": "短い日本語。参照したrawのGit SHAを併記"
}
```

- 上の例は形式例であり、実際の買い目や馬番ではない。
- candidatesには snapshot の出走馬の全頭を入れ、枠外の馬はframes:[]、evidence省略可。枠内の馬だけ発走前根拠を付ける。
- created_atは作成時点、snapshot_ref.frozen_atは実ファイルの文字列を保持。公開リポジトリのためURLクエリ・トークン・サイト本文の丸写しを入れない。
- 券はframe_tagを必ず持ち、候補にない馬／取消馬の馬番を含めない。betの合計は500、passの合計は0。元の源さんの券はこのJSONの bets に混ぜない。

## 8. 評価と改版

- コミット済みv1が発走前に記録された対象レース30件が貯まるまで優劣の結論を出さない。記録の有効件数には bet と（情報十分で意図して選択した）pass の両方を含め、bet件数・pass件数も別掲する。情報事故・発走後記録・未コミットは分母に入れない。
- 各レースで固定比較：同一race_idの現行Champion源さん（500円） 対 scenario-frame v1（500円上限）。現行源さんのbaselineは発走前snapshotから取得し、結果が出てから作り直さない。
- 30件チェックポイントで集計：①投資額／払戻額／回収率（見送り投資0含む）、②的中レース率と高配当外れ値への依存、③実際の3着以内馬に対する A/B/C の候補捕捉率と枠別件数、④採用候補にはいたが馬券にならなかった conversion loss、⑤主軸への集中（馬券ごとの馬番採用回数）、⑥欠損率とpass率、⑦現行源さんと同じレースでの勝ち負け・差額。30件は「判定の最初の点検」であり、優位性が統計的に証明されるサンプル数ではない。
- v1を書き換えない。改善案はv2候補メモにのみ記録し、v2を採用するなら別のrule/commitで事前登録する。10/10の2レースは開発時に結果を見たのでv1の検証対象にしない。同一レースの記録を15:00の見立てや結果で更新しない。
- 原則GitHubの編集・push・mergeはClaudeが担当、ChatGPTは監査・予想作成（read-only）。
